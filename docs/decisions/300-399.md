### 313. Potions are programs: a potion's use is read from its OnUse and run between the game's potion hooks — active (2026-11-25)
The owner's decision: drinking or throwing a potion is a decision the mod previews, so the simulator models it like a card play, read from the game's code. A potion's use is a `SimPlay` with `Potion` set (`SimPotionUse`: its class, whose it is, its target), compiled to a `PotionUseAction` (`SimEngine.RunPotionUse`, from `PotionModel.OnUseWrapper`): it leaves its owner's belt (`RemoveBeforeUse`: `SimPlayer.Potions` one fewer, `SimPlayer.Fairies` one fewer for a Fairy in a Bottle), `Hook.BeforePotionUsed`, its body, the game's log of it (`History.PotionUsed`), then `Hook.AfterPotionUsed` while its owner lives. No card is played: nothing of a card play's runs around it. Both potion hooks reach every listener whatever the fight's state (they loop over the run's listeners: `SimEngine.HooksAfterTheFightEnds`). The body is the potion's `OnUse` read with the card program reader (`ProgramReader.Read(type, read, "OnUse")`), each command translated by `SimAdapter.Potion` into the simulator's actions for that command (damage to its target or every enemy, block to the player it's given, a power on whom its code names, draws, energy, stars, orbs, Osty, a heal), its amount from the potion's own values on the board; a command, a target or a condition it can't follow makes the use unknown where it runs (`?` with the reason), never dropped. The potion hooks are read from the listeners' code like any other (`HookName.BeforePotionUsed`, `AfterPotionUsed`: Reptile Trinket and Belt Buckle now read whole, `potion.Owner` the hook's player, `Owner.Potions` a new fact `OwnerPotionCount`); Surrounded's hand-written model answers `BeforePotionUsed` as its code does. `AfterPotionProcured` and `AfterPotionDiscarded` are hooks the simulator never runs (`HookReader.NotRun`): no simulated decision procures or discards a potion without its outcome being unknown where the hook is overridden.
*Why:* the contract (decision #92) covers every decision you could make right now, and drinking a potion is one; its effects are code like a card's, so the same reader and the same actions follow them (effects, not cards). Two translators were weighed: making the card translation (`SimAdapter.Steps`, built around a `CardModel`) take any model, or a narrow translator over the same actions for the commands potions call. The narrow one was taken for now (it touches no card's play: the protected snapshots stay as they were); folding the two together is a TRACKER item.
