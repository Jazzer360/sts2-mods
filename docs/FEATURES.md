# Spire QoL: feature reference

This is the complete list of every change Spire QoL makes to the game. If a change isn't here, the mod doesn't make it. Each feature lists what you see, its settings, which game UI it touches, and the game methods it patches.

**Status key:** 🟢 shipped · 🟡 built, being tested in game · ⚪ planned

Spire QoL is **display-only**. It never changes game state, damage, cards or saves. Its manifest sets `"affects_gameplay": false`, so you can join multiplayer lobbies whose players don't have it. See [MODDING_NOTES.md](MODDING_NOTES.md).

**Only knowable information.** Spire QoL shows only what a player with perfect memory and full knowledge of the game's rules could work out. It never reads the RNG or the seed, the draw pile's order, or an enemy's move beyond the intent on screen. Random effects show their amount, never their target or roll, and predictions that would depend on a roll leave it out.

**Harmony patches: observe-only.** Every feature works by reading live game state once per frame and drawing its own nodes. Nothing in the game's code is replaced or changed. Six patches only record a call: `CardPileCmd.Shuffle` (the proc audit counts shuffles, and the predictions forget the known top of your draw pile; the game keeps no record of them), `CardPileCmd.Add(cards, pile, position, ...)` (the predictions remember cards placed on top of your draw pile, decision #91), `EventOption.Chosen` (Run Reminders checks which relics react to the option you chose; a postfix keeps the option's task to know when it ends) `HealRestSiteOption.OnSelect` (Rest Preview checks your HP after resting) and `MendRestSiteOption.OnSelect` (a postfix too: Rest Preview checks a teammate's HP after your Mend). The coverage check reads the game's compiled code (reflection, `PatchProcessor.GetOriginalInstructions`), which changes nothing.

## What the mod adds to the game, technically

- **One CanvasLayer** (`SpireQoL_Overlay`, layer 10) under the scene tree root, holding a toast message and a `SpireQoL_Widgets` container for the floating widgets. **During live combat with no screen open, that container is moved inside the game's `NCombatUi`, directly before the `%Hand` node, so your cards draw over the widgets.** It moves back to our layer when combat ends, when any screen opens over combat, and while the layout is unlocked (so the hand can't swallow drag clicks). It also steps out the moment `NCombatUi` leaves the scene tree (its `tree_exited` signal, before the game frees it: a co-op game over can free it with combat still running) and never moves into a node queued for deletion (decision #102). Widgets attached to a game element read that element's screen position each frame; they never modify it.
- **Floating widgets hide while a game screen covers combat:** the pause menu, draw/discard/exhaust pile and deck views (`NCapstoneContainer.InUse`), card rewards and card-choice screens (`NOverlayStack.ScreenCount > 0`), and the map (`NMapScreen.IsOpen`). Card decorations live on the card nodes in your hand, so they already sit underneath those screens.
- **A second CanvasLayer** (`SpireQoL_Settings`, layer 100) for the settings menu, hidden until opened. While the menu is open it registers itself with the game's `NHotkeyManager` as a blocking screen (`AddBlockingScreen` / `RemoveBlockingScreen`, the game's own mechanism for popups), so game hotkeys do nothing, and pushes its own Esc / back binding (`ui_cancel`, `mega_pause_and_back`, `mega_back`) to close it; both are removed when it closes.
- **Two "Spire QoL settings" buttons** (plain Godot `Button`s) added as children of game nodes while those screens are open: the Mods screen's info panel (`NModdingScreen` → `%ModInfoContainer`, only while Spire QoL is the selected mod) and the pause menu (`NPauseMenu`, bottom-left). Found each frame from `NGame.Instance.MainMenu.SubmenuStack.Peek()` and `NCapstoneContainer.Instance.CurrentCapstoneScreen`.
- **One `SceneTree.ProcessFrame` callback.** It runs each feature, then draws card decorations.
- **A child node `SpireQoL_CardOverlay`** under `%CardContainer` of each card node in your hand that has something to show. While an Ethereal card is shown faded (decision #113), a copy of it (the game's card scene `res://scenes/cards/card.tscn`, the same model, drawn by the game's own `NCard.UpdateVisuals` with the card's pile and preview target) is drawn at full opacity into a `SubViewport` of ours (`SpireQoL_FlatFadeView`), and that image (`SpireQoL_FlatFade`, a `TextureRect` in the container, over the glow and the tabs' layer) is drawn at the Ethereal opacity, while the container's own layers have their `Modulate` alpha set to 0 (the card stays in place, so hovering and playing it are the game's own; the glow and the tabs stay drawn). The copy is drawn again only when what the card shows changes. A card that can't be copied has the container's `Modulate` alpha lowered instead (each layer faded on its own). Everything is restored as soon as the node stops showing that card. The game reuses card nodes, so this matters.
- **A subscription to `CombatManager.CombatSetUp`,** to know the current combat.
- **One file**, `mods/SpireQoL/SpireQoL.settings.cfg` (JSON). Never written to game saves. New on-card tab kinds are added to it as they first appear (saved at most every 3 seconds).
- **Three checks write to the game log** (`godot.log`, lines start with `[SpireQoL] [audit]` or `[SpireQoL] [coverage]`) when something doesn't match what the mod expects, to surface bugs and gaps:
  - **Forecast audit:** (a forecast still on its way when your turn ends, past the audit's 8 ms wait, is kept searching and built when the turn is checked; one that never had a result, or whose search stopped at a cap, is counted as not checked: decisions #104, #107) the Incoming Damage forecast from the last moment of your turn (before any end-of-turn effect: in multiplayer the game waits for every player between its two end-of-turn phases, and your turn is over from the first, `PlayerTurnPhase.End`), against the HP you and Osty actually lost by your next turn (from the game's combat history). A mismatch logs the forecast breakdown and every damage and block entry. The forecast is the simulator's worst branch, not capped by your HP: a hit that kills you (Fairy in a Bottle brings you back) counts its overkill too. HP lost (yours or Osty's) anywhere between the best and worst branch isn't a mismatch, since a random target decides which happens. When every number is inside its range, they must also come from **one** branch (one set of random targets explains HP lost, Osty's, and every enemy's HP, hits through block and death together); otherwise it's reported as "no single branch". Your end-of-turn auto-plays are checked too (the branch must have auto-played as many cards); a turn where one came up that the simulator couldn't play (a pick that changes your hand) or where the count matches no branch isn't checked.
  - **Outcome audit** (part of the forecast audit): the outcome simulator's prediction from that same moment, enemy by enemy, against the history: dead before it acted (predicted in every branch but it acted, or in no branch but it died first; one your Thorns kills during its own attack acted, since its hit still lands; this is what checks the lethal tab), its HP when your end of turn was over and the damage instances that got through its block then (what Slumber and Asleep count), counted up to the hit that killed it (an enemy that comes back, such as the Waterfall Giant with Steam Eruption, takes later hits outside the simulated fight), against the branches' range, and for Imbalanced enemies whether its first hit was fully blocked when every branch agreed. Only what no branch allows is reported, so a random target never causes a report; if the simulation was truncated, only the guarantees it still makes are checked. Reports carry the simulator's per-enemy prediction, its exact start state as JSON (to replay offline: `tests/SpireQoL.Sim.Tests/Cases`), and the full numbered history window, enemy turn included. Every enemy turn also writes one `[audit] [outcome]` line to the log, predicted vs actual for each enemy, matched or not.
  - **Forecast audit** also checks the end-of-turn block it predicted, and splits the history by whose turn each entry happened on, so Poison ticking at the start of your next turn isn't counted.
  - **Proc audit:** the tabs a card had on its last frame in your hand (every tab the mod predicted, including ones hidden in settings) (a play can start several frames after the card leaves your hand, while the game's action queue is busy), against what the play did. A card play is one action in the game's action queue (`PlayCardAction`): spending its cost, "before play" procs, the card, "after play" procs, exhausting or discarding it, and every draw or effect its hooks set off. Everything that happens while that action is running belongs to the play: history entries (`CombatHistory.Changed`), relic and power flashes, and shuffles (`ActionExecutor.BeforeActionExecuted`, and again when it resumes after a choice such as Burning Pact's pick). Potions and ending your turn are other actions, so they never mix in. The play is checked when its action finishes (`GameAction.AfterFinished`), against a prediction rebuilt the moment its action starts, from the board at that moment, through the same code as the card's tabs (decision #28): nothing is pending ahead of it, so plays made while another was resolving are checked like any other. When the fight is ending as the play finishes, the state after it isn't compared (the fight's cleanup changes it); the history checks still run, but less proc damage or block than predicted isn't reported then (the game stops logging history from the hit that ends the fight, `CreatureCmd.Damage`), only more. Cards auto-played by it, such as Catastrophe's, are part of its action. **Tabs shown (decision #103):** the proc tabs the card showed on its last frame in your hand are held to that same prediction, when nothing came between them (no combat history entry since that frame but the play's own start) and both simulations finished: from the same board through the same code, they must be the same tabs, crossed or plain, aim marker, number. A difference is reported as `tabs shown` (a tab drawn from an old frame or a cache keyed on too little, which checking the outcome alone can't see). Skipped otherwise, and counted in the combat summary with the reason (the board changed since they were drawn, a simulation not finished in time or stopped at a cap, tabs held from an older result). When that prediction can't be rebuilt, the play is checked against the tabs it last showed in hand; if another play or a potion finished after those were computed, its mismatches are logged as `[model]` lines, not reported. Simulator tabs (lethal, Imbalanced, wake) of a card whose simulation had no result yet when the audit stopped waiting (8 ms, its own wait: decision #104) aren't reported either. Block from Frost orbs the card evokes counts as its own. Damage caps (Hard to Kill, Hardened Shell, Intangible) flash when they cap a hit; they aren't procs, so they're not reported as missing tabs. Neither is Show Off, whose flash on a kill only raises the Show Off card's Aim for a later play. Powers enemies apply to each other (Heist) aren't the play's doing, nor are powers a kill gives back by no one (Possess Strength returning the Strength it took). **Random outcomes aren't reported:** when a play's result depends on a roll with more than one possible target (a random-target proc such as Juggernaut, Kusarigama, Tingsha, Forgotten Soul; a Lightning evoke; a random-target attack; all with several enemies alive), only effects the combat history shows a random hit caused are logged as a `[model]` line instead of a mismatch: an enemy power firing after that enemy took random damage (no card source, or this card's random-target hit) or after a random kill; Gremlin Horn, extra summons, draws, cards or powers after a random kill. Everything else in that play, and every play without randomness, is still checked, so multi-enemy fights still verify their tabs. Reports are grouped by cause: which powers for "unexplained powers", and more or less than predicted for amounts. It logs: a relic or power that fired with no tab; a relic tab whose relic didn't fire; proc block that differs (exact; block from any card's own play, including the next one and auto-played ones, isn't proc block); proc damage outside the tabs' predicted range (to enemies and to you); and a **budget** check: draws, exhausts, discards, created cards, orbs, summons and powers applied beyond what the card itself does plus what its tabs can add are logged as "unexplained" (a missing tag). Fewer draws or orbs channeled than predicted is reported too, since neither is a choice: except when the fight ended, when fewer cards were exhausted than the most it could (draws per exhaust), or when you have no orb slots left. Fewer exhausts, discards or created cards than predicted are only logged (those are often "up to" counts you choose). The game logs a transformed card (Begone, Charge, Guards, Seance, Compact, Primal Force) as created, so up to what the card can transform counts as its own created cards there; nothing else treats a transform as a created card (the game's created-card hook doesn't fire for it). A card's own powers are its power values plus every power its own code applies (`PowerCmd.Apply<T>` calls, read from the compiled card class). Windows with auto-played cards skip the budget: those cards are random, so nothing predicts them. Less than the card's own is a `[model]` line (our model of the card is off, or a pile ran out). Draws are checked against all the draws the play sets off (Dark Embrace and the rest, see [Shuffle Warning](#shuffle-warning)), so their tabs no longer excuse extra draws; powers that react to which card is drawn (Pagestorm, Iteration, Hellraiser, Chains of Binding) firing on a play that drew are noted, not reported. **Shuffle:** whether the play shuffled your discard pile into your draw pile (an observe-only prefix on `CardPileCmd.Shuffle`: the game writes no history entry for it) against the prediction behind the Shuffle Warning; a predicted shuffle that didn't come because the play ended the fight is only logged. **State after the play:** when the play's action finishes (it has fully resolved, nothing else has run), the simulator's state is rebuilt from the game and compared with the simulator's own prediction of that play (the same start state and play behind the card's lethal, Imbalanced and wake tabs): each enemy's HP, block, poison, Flutter and intent (its hits as they would land on you in the predicted state, so what the play changed counts: Weak, Tainted, Conductor's Baton), your block, Plating, Juggernaut, Thorns, Flame Barrier, Feel No Pain, orbs (a random Chaos orb matches anything), Osty (not after a summon), and in multiplayer each living teammate's block and HP (Beacon of Hope's share). Random targets are branches; only a state no branch gives is reported, one issue per difference from the closest branch, with both states as JSON. Not checked with auto-played cards. A card aimed at a teammate (`AnyAlly`, such as Ignition: the Plasma goes to their orbs) isn't checked against its prediction while the simulator applies it to you: the play's differences are logged, and the coverage check lists the card. **Every power:** every power on every creature is snapshotted when the play's action starts and when it finishes; a power that went down or away with nothing in the play to explain it is reported (grouped by power). Explained: powers the card (or a card it auto-played) applies, powers that flashed (they acted), sources with a tab, Artifact when the card applies debuffs, temporary powers, the simulator's own powers (compared above), and anything on a creature that died. **Another action inside your play (decision #29):** while your play waits for your choice, the game can run a teammate's queued action; its history entries and flashes are kept out of your play, and for that play the snapshot checks (state after the play, every power, everything else) are logged with the action that ran instead of reported, and counted in the combat summary. **Everything else:** energy, stars, gold, every creature's HP and max HP, every card of yours (pile, cost, upgrade, keywords, affliction, enchantment) and every relic's counter and status, before and after the play. The played card's cost going back up is the game clearing its "this turn or until played" cost (Splash, Bullet Time), not a change to explain. A change must be explained by code that ran: the card's own class, a source with a tab, a source that flashed, a card it auto-played or drew (and its enchantment), or a source that reacts to draws when it drew; each is checked by whether its compiled code issues the game command that makes that change (`CodeIndex`). Anything else is reported as "untracked" with the sources present whose code could have done it, grouped by those sources. A relic whose counter or status changes with no tab, tracker row or flash is reported too (goal 2). **Crossed relic tabs (decision #117):** a tab for giving up a relic's bonus is held to what the game shows, both ways: Art of War, Ripple Basin and Pael's Eye going dark (their Active status cleared by the play), Pael's Tears by the energy the play spent and what's left once it's over; Biiig Hug, which flashes, by its flash. Your energy after the play (and each teammate's) is compared with the prediction in the state after the play.
  - **Coverage check** (`coverage-watch`): every game class (relic, power, card, monster, orb, potion, enchantment, affliction) that overrides a combat hook (`Diagnostics/CoverageHooks.txt`: events and rules during a fight that the game's own damage, block and play-count math doesn't already cover) has an entry in `Diagnostics/CoverageLedger.cs`, written from its hook bodies in the decompile: covered (and by what), ignored (and why it can't change a prediction), or a known gap. When the mod loads, the running game's classes are compared with that ledger by reflection, on a worker thread: a class that's new, whose hooks changed, or that has no entry is unexpected, and the first time it shows up in a fight (a relic you have, a power on anyone, a card in your hand, an enemy, an orb, an enchantment or affliction on a card) it's logged and reported once. Known gaps are logged when present, not reported. Card code is checked too: every card's play code (read from the compiled game) is compared with what the mod counts for it, through the same functions the predictions use (draws, orb channels, block, poison, Weak, exhausts, discards, created cards, Sovereign Blades from forging, transformed cards, stars, an attack's hit count when its code sets none and it has a Repeat value), on the card and on an upgraded copy (a card that only does it when upgraded counts), and a card whose code does something uncounted is reported when it shows up. The settings are checked at load: every proc rule (read from the compiled rule code), tracker row and double-play source in the game has a settings row, every row still has something behind it, and every feature has an on/off switch; a tab kind shown in play that the settings don't describe is reported as it appears. A summary line at load gives the counts, and a warning when the game's version isn't the one the ledger was made from. **Relic tracking** (goal 2): every relic that can affect a fight (any public hook outside `Diagnostics/OutOfCombatHooks.txt`) has a tab, a tracker row, or a reviewed reason in `Diagnostics/RelicTracking.cs` ("none: ..." or "gap: ..."), written from its hook bodies; one with none of these, or one new in a game update with fight hooks, is reported when you have it. Cards aimed at a teammate or at every player (`TargetType.AnyAlly`, `AllAllies`) are listed until the simulator models their effect on teammates (it applies them to you); those are reported only in fights with other players.
  - **Teammates (multiplayer):** the forecast check also compares each teammate's HP lost over the round, and their Osty's, with their predicted range, on every game (decision #30: Teammate Incoming Damage shows it, and a teammate is simulated through its own path). The check uses the cards in their hand whatever the setting (decision #25); the log line also gives the range shown, when leaving their hand out made it differ. Skipped when a teammate auto-played a card at end of turn (Stampede). When you auto-played cards from your hand (Stampede, Simpleton: a random card at a random target), the check keeps only the branches that picked the same cards at the same targets, as the game's history shows them (decision #86); a mismatch when no branch did. The turn isn't checked only when the pick that happened drew or made cards (what follows it isn't simulated), or for an auto-play from another source; the log says so. A turn followed by an extra turn (The Hanged Man) has no enemy turn to compare and isn't checked. A forecast whose search stopped at a cap (decision #107) showed `?` and promised nothing past what was settled, so its turn isn't checked (counted; the cap itself is reported). A forecast with a branch it didn't model isn't checked. Every turn not checked is counted by reason in the combat summary (`enemy turns not checked: ...`), and so is what the forecast didn't model (`not modelled in the forecast: ...`, each also logged as `[audit] [gaps]`): decision #92, gaps to close, not passes. A turn that ends in your death is checked as soon as you die (the fight ends before your next turn): your death against the forecast's (a mismatch when no branch had you dying), and each enemy's death before acting and HP at your turn end as usual; the HP you lost isn't compared, since the hits after your death never came.
  - **A card with no simulation** (building it failed, reported as a crash on its own): its checks of the simulator's tabs are skipped and counted (`no simulation for this card`), not reported again.
  - **Every indicator's states (decision #95):** the lethal tab is held to the end of turn simulated from the board the play left (an enemy dead in every outcome of the card must be certain to die from it; one alive in every outcome must not die). Every tabbed source the play sets off in every outcome, powers and crossed tabs included, must flash when its code flashes in a hook of its own (`didn't fire`; a flash only after changing a hit's damage or block, as Slow's, doesn't count: the damage and block checks cover it). A proc set off by a random hit or a drawn card is excused only when some outcome the simulator explored set it off. Each death chance the end-of-turn forecast shows between 0 and 100% is logged with what happened (`[audit] [odds]`) and totalled per fight and session; a total far outside the chances (more than 4 standard deviations, over 30 or more) sends a report.
  - **Summaries:** at the end of each combat, one line per audit: `card plays checked, N matched (issue counts)`, `enemy turns forecast, N matched`, and `chances: N shown, M happened, expected X–Y`.
  - Both only read the combat history and subscribe to relics' and powers' `Flashed` events. They're the features `forecast-audit` and `proc-audit`, on by default.
- **Error reporting** (setting `ReportErrors`, on): crashes caught anywhere in the mod (feature errors, frame errors, tag layout, play facts) and every audit mismatch are sent to the mod's own Sentry project. A report is built on the game's thread (it reads the game's state) and handed to Sentry from a background one; a mismatch carries no captured stack; a report that takes 20 ms or more to build logs which stage took it (`[perf] building a ... report took`). A game member the build names that the running game doesn't have (another game version or branch) groups as one report per member, wherever it failed. Every report is tagged with the mod and game versions, and how many players were in the fight and their characters (yours first), so multiplayer reports can be told apart; they get a `multiplayer` label and their own per-session budget (at most 40 each, single-player and multiplayer), so a co-op session can't use up the reports a single-player fight would send. Proc audit reports also carry the full window: every history entry from just before to just after it, numbered by position and described in our own words (the game's text for a draw says "discarded"), with relic and power flashes at their positions and markers for the window and the play's start; what the card itself was expected to do (draws, exhausts, orbs, hits, orb evokes, random outcome); tabs hidden by settings; every play this turn so far (card, its tabs, matched or what didn't), the state just before the play started (player, powers, relics with their counters, orbs, enemies, hand with tabs), how many frames passed between the card's last frame in hand and its play starting, and the history entries of the play's action. Each report carries the game state from `Diagnostics/Snapshot.cs`: combat, player, powers, relics, orbs (front first, with passive and evoke values and slot capacity), enemies with intents, the hand with each card's tabs and play facts, the last 40 combat history entries, the audit window, and the last 80 mod log lines. It uses the game's own Sentry .NET (`Sentry.dll`) through a separate `SentryClient` with our DSN. `SentrySdk.Init` is never called, so the game's own reporting is untouched and no global handlers are installed. There's no machine name, user or personal data. Each fingerprint is sent once per session, at most 40 events. Mismatch fingerprints leave out amounts, so the same bug groups into one issue. Mismatch reports also carry searchable tags: `card` (the card played), `check` (which check failed), `source` (the relic or power the issue names), `effect`, `encounter` and, for the forecast check, `monster`. Every report is also tagged `other_mods` with the other mods loaded (id and version). While another loaded mod changes the game (its manifest says `affects_gameplay`, or leaves it out, the game's default; or its code adds game content: any card, relic, power, monster or other model), no mismatch is sent, and a crash is sent only when none of that mod's code is in its stack (a frame in its assemblies, or a game method it patches): our code failing on a modded game still reaches us. A mod listed in `reporting.json`'s `gameplayMods` counts as changing the game whatever its manifest says (decision #97). Reports carry `gameplay_mods` too. The log says once what wasn't sent and why (`core/Game/OtherMods.cs`, decisions #34, #96). Handlers on the game's own events and every patch body catch their exceptions, so nothing of ours throws into the game's code. Nothing is sent from a build older than the oldest version reports are still taken from: at startup the mod reads `reporting.json` from the repo on GitHub (one request, the mod name as the user agent, nothing about the player; `core/Diagnostics/ReportFloor.cs`, decision #81), and until it answers, or if it can't be reached, reports go out as usual. An hourly GitHub Action mirrors new Sentry issues to GitHub issues (`auto-report`).
- **Session summaries** (decision #108; feature `session-summary`, "Session summary" on the General page, on; sent only while `ReportErrors` is on too): at the end of each play session (a run started or continued, until it's left: save and quit, back to the menu after a win, a death or abandoning it, or the game closing) that had a fight turn, one summary of counts goes to the same Sentry project: fights and turns (each turn clean, unchecked, capped or mismatched, from the audits), the checks done and skipped (with the reasons, the most frequent 15), the simulator's searches (how many, in the background, cancelled, caps, time percentiles, the slowest, the most states held), the frame's waits, how long the board took to settle when it didn't in its frame, the mod's time per frame and the game's own stalls, garbage collections, reports sent, the session's length, players, your character, the CPU's core count and whether other mods were loaded. Nothing personal, no game state. It's sent outside the per-session report limits (one per session). The summary so far is kept in `mods/SpireQoL/SpireQoL.session.json`, rewritten at each turn and fight: a session the mod didn't see end (a crash) is sent on the next launch. The log gets the same counts (`[session] ended`). The hourly GitHub Action adds the summaries up per version in a pinned issue (`session-metrics`). Fed by an in-process event stream (`Telemetry/DevEvents`) that the audits, the simulator and the reporter post to, and by the overlay's frame timing (`OverlayHost.FrameMeasured`). The session's bounds are read from `RunManager.IsInProgress` and its private `State`, how it ended from `IsAbandoned`, `IsGameOver` and `HasRunEnded` (beta branch only; read by reflection). No patches.
- **Dev mode** (decision #108; hidden setting `DevMode`, not in the menu): on when a developer's install left `SpireQoL.dev` beside the DLL (release zips never contain it), or when `DevMode` is `true`; `false` turns it off. Reports and session summaries from that game are tagged `dev`, and the session metrics leave them out. Nothing from that game goes to Sentry: each report is saved as `reports/{id}.json` in the dev folder instead (everything the event would have carried), and each session summary as a line of `sessions.jsonl`, whether `ReportErrors` is on or not (`ErrorReporter.Local`). It writes the dev dashboard's files to `%USERPROFILE%\SpireQoL-dev` (or the hidden setting `DevFolder`; `Telemetry/DevSink`, `DevDashboard`): the event stream with frame rollups (each feature's time per frame, from `OverlayHost.FeatureMs`) and the mod's log lines (`ModLog.Written`), a state snapshot (where you are, the session's counts, the turn forecast now), and keeps the reports and session summaries. The page, `tools/dashboard/index.html`, isn't part of the mod (docs/DEVELOPMENT.md "Dev dashboard"). With dev mode off none of this runs.
- **Error logging is capped:** a failure that repeats every frame is logged in full once, then as a count every ~600 repeats.
- **Slow frames:** the mod times its own work each frame (each feature, the post-frame callbacks, widget layout). Every frame where that took over 30 ms logs a `[perf] slow frame` warning with the time per feature. Over 50 ms it's also reported as an error report (`perf`, grouped by the slowest feature, with the usual game state), from that feature's second such frame in a session (the first can be its code warming up); a freeze of a second or more is reported the first time. A frame over 50 ms where the mod's share stayed under 30 ms is the game's own work (a slower PC, loading, room changes): logged as an info line, at most one every 2 seconds with a count of the ones in between, and never reported.
- **Observe-only patches.** Prefixes that record the call and change nothing: `CardPileCmd.Shuffle` (proc audit; the predictions forget your draw pile's known top), `CardPileCmd.Add(IEnumerable<CardModel>, CardPile, CardPilePosition, AbstractModel, bool, bool)` (the predictions remember cards placed on top of your draw pile: decision #91), `EventOption.Chosen` (Run Reminders check) and `MonsterModel.RollMove` (Intent Forecast check: works out the forecast before the roll); postfixes that only read: `EventOption.Chosen` (keeps the option's task to know when it ends) and `MonsterModel.RollMove` (compares the rolled move with the forecast); everything else is read from live game state each frame; the game's hook queries it calls (`Hook.ModifyCardPlayCount`, `ModifyBlock`, `ModifyDamage`, `ShouldEtherealTrigger`, `ModifyOrbPassiveTriggerCount`) are pure queries with no side effects.

## On-card tabs: one language for everything on a card

**The question every tab answers: does something happen the moment I play this card, right now?** Exceptions: the Retain tab, Ethereal translucency, and the tabs on cards you're offered outside fights (below: "this relic makes this card stronger", decision #62).

Every indicator about a specific card in your hand uses the **same form**: a **tag** hanging up off the card's **top edge**, centered in a row, one tag per effect. In a fanned hand the tops of cards stay visible while their sides are covered, so you can read the tags at a glance without hovering. A tag means something out of the ordinary will happen when you play that card.

- **Look:** each tag is a copy of the card's own enchantment tab (the game's banner art), always at full color (never the grey the game gives a disabled enchantment), rotated a quarter turn so it hangs off the top edge the way an enchantment tab hangs off the side. **It draws beneath the card art but above the card's glow**, tucked about 17% under the top edge, so the card itself covers the tucked part. The icon is drawn slightly smaller (85%) and sits just below the middle of the part of the tag that shows above the card. Tags stay on a card while you hold it to play it (dragging or aiming): the game moves a held card out of the hand's holder container (`NPlayerHand.StartCardPlay`), so the held card is found through the hand's current card play (`NPlayerHand._currentCardPlay`, read only). Each tag carries the icon of whatever is affecting the card: a relic, power or enchantment, or the draw pile.
- **Text instead of an icon only for replay:** replay on the card itself has no power or relic to show, so its tab reads `2×` (total plays). The text fills the icon's slot (the tab's own auto-sizing label gets the icon's box and a larger maximum font size).
- **Numbers only for amounts:** a tab shows a number only when the proc gains you block, deals damage or summons, and the amount is the point (e.g. Feel No Pain on True Grit: `3`). Free-card tabs show the energy the free card saves, or `?` when you couldn't know what the card costs, which the free card hides (Snecko Eye, Frantic Escape; decisions #44, #47, #54). It sits at the icon's lower-right corner, like a power amount. Everything else is icon only.
- **Plain vs crossed:** a plain tab means playing this card does something extra. A crossed tab (red slash) is a warning: playing it might be bad for you, because it helps the enemy (Enrage, Curl Up), hurts you (Thorns, Galvanized) or gives up a relic's bonus (Art of War, Pael's Tears).
- **Aim marker:** a tab whose effect happens only at some of the targets you could aim the card at (enemies, or teammates for cards aimed at them) gets the head of the game's targeting arrow over its icon's top-left corner (decision #55), at 60% of the icon's size and reaching past its top and left edges, clear of the slash and the number. Each target is simulated on its own: the tab shows when some target gives it (every random branch for good tabs, any branch for warnings), and the marker when not every target does. So a lethal skull, Mighty Wings or a Curl Up warning with the marker means "aim at the right one" (or, for a warning, "aim elsewhere to avoid it"). Several enemies sharing a tab get the marker only when some target sets off none of them. Untargeted and random-target cards never get it.
- **Heal marker:** the game's top-bar heart in the same corner, on a card reward's Book of Five Rings tab when taking that card makes it heal now (decision #83); crossed when part of the heal is wasted.
- **One per source:** each source shows at most one tab per card. Tabs keep their size and spacing; if a row would be wider than the card, only the gaps shrink (tabs overlap, later ones on top), so a row never spills past the card's edges.
- **Not tabs:** the only on-card effect that isn't a tab is **Ethereal translucency**.
- **Not marked: cards that can't be played.** The game already crosses out the cost of a card that can't be played for any reason other than cost (`NCard` unplayable energy/star icon) and drops its glow, so there's no tab for it (removed in 0.23.1).

## Card Indicators

**What you see:** mid-combat changes to a card in your hand that the game otherwise shows only as text, as on-card tabs (see above).

- **Ethereal cards are translucent** (80% opacity by default) when Ethereal is on the card itself: cards that are always Ethereal, and Music Box copies. **Not** when Ethereal comes from Hex (the act 3 elite's Hexed affliction): Hex makes every card Ethereal through a power (a "global" keyword source), and the game's affliction overlay already marks those cards.
- **Retain:** a Steady tab (Steady is the game's Retain enchantment). **Sly:** a Master Planner tab (the de-facto Sly power). Granted-for-this-turn (Expertise, Hand Trick) looks the same.
- **Replay** on the card itself (Hidden Gem, Transfigure, Sword Sage on Sovereign Blade, enchantments): a text tab `2×`, the card's total plays (`CardModel.GetEnchantedReplayCount` + 1). The card text says "Replay", but it's easy to miss without hovering.
- **Added keywords get no tab:** the game prints every keyword a card currently has (including added Exhaust) on the card itself. (The Goopy "added Exhaust" tab was removed in 0.21.0.)
- **Blocked cards** (Bound, Ringing, Smog, Velvet Choker): no tab since 0.23.1. The game's own crossed-out cost shows it whenever `CardModel.CanPlay` fails for a reason other than cost, which covers every case the old tab did.
- **Galvanized** moved to [Proc Indicators](#proc-indicators) in 0.19.0 (crossed Galvanic tab with the damage you take).
- **Double play:** one tab per source, with that source's own icon: the power (Echo Form, Burst, Duplication, One-Two Punch, Signal Boost, Tag Team, Ki Verse) or the relic (Throwing Axe). Replay on the card itself is the `2×` tab instead. The game's query reports which models changed the count, so new sources get their own icon automatically.
  - The count comes from the game's own play-count query, the one it runs when you play the card: enchanted replays + 1, then `Hook.ModifyCardPlayCount`. So it covers Echo Form (first N cards each turn), Burst (skills), Duplication, One-Two Punch (attacks), Signal Boost (powers), Throwing Axe (first card each combat), Tag Team, enchantments, and anything added later.
  - Not on a card that can't be played (curses, Unplayable statuses, cards blocked outright), the same check the proc tabs use; the `2×` tab neither.
  - Tag Team only doubles attacks aimed at the enemy that has it. Single-target cards are checked against each enemy, and the best case is shown.

**Not yet:** free-this-turn / free-this-combat / temporary-cost duration markers, decorations outside the hand (draw/discard views).

## Relic Counters

**What you see:** a compact tray, by default attached just right of your HP bar with its bottom edge level with the bar's bottom (so it stays clear of enemies); when you have Osty (Necrobinder), it sits just right of Osty's HP bar instead, since Osty stands to your right (only at the default placement: once you move or re-pin the tray it's always measured from your own HP bar, and Osty's bar stays up reading "Dead" when Osty dies, so the tray doesn't jump), with one row per counter relic or countdown power you have: its icon, a bar split into one segment per step, and a short label. Counters longer than 12 steps (Cacophony's 33) show only the countdown number, no bar.

**What belongs here:** counters you push forward by playing (cards, attacks, skills, energy, draws, orbs, stars, exhausts) and per-turn card limits. On/off relic states are on-card tabs instead (Pael's Tears, Pael's Eye, one-shot relics), and relics that just count turns are opt-in (Tracker checkbox per relic in the settings menu, off by default).

- **Counters that carry across turns and combats sort first:** Pen Nib, Nunchaku, Tuning Fork, Iron Club, Galactic Dust, Joss Paper, Metronome.
- **Then per-turn counters:** Kunai, Shuriken, Ornamental Fan, Kusarigama, Letter Opener, Brilliant Scarf.
- **The row flashes when the next qualifying action fires the relic.** This uses the game's own "about to fire" state (`RelicModel.Status == Active`). Pen Nib flashes at 9/10. Stone Calendar flashes all of turn 7.
- **A row goes away when the game hides the relic's counter** (`RelicModel.ShowCounter`): Metronome once it has fired this fight, Brilliant Scarf once it has fired this turn.
- **Limits:**
  - Velvet Choker shows plays left and turns red at 1.
  - Pocketwatch shows green while you're within its card limit and red ("missed") once you go over.
- **Make It So** (a card, shown with its tiny card while a copy is in your fight's piles, an Attack Potion's too): your Skills played this turn toward its next return (every 3rd; each play of a replay and auto-played Skills count), "back on the next" and flashing when your next Skill brings a copy back, "(in hand)" when every copy is in your hand. Settings: Cards page, Tracker column.
- **Turn timers** (off by default; switch each on in the settings menu, Relics page, Tracker column): Horn Cleat, Candelabra (turn 2); Captain's Wheel, Chandelier, Sparkling Rouge (turn 3), Pael's Flesh (1 more energy from turn 3), shown with progress and "next turn" the turn before; Stone Calendar, Happy Flower, Fake Happy Flower, Pendulum, Pollinous Core as counters.
- **Countdown powers** (sorted after relics; the game's `PowerModel.DisplayAmount` is "steps left"). The bar fills toward the next trigger and flashes when one step is left:
  - Across turns: Orbit (every 4 energy spent), Automation (every 10 cards drawn), Cacophony (every 33 cards drawn, number only).
  - Per turn: Panache (every 5 cards played), Pale Blue Dot (5 cards played, any type; shows `done` once it has fired this turn).
  - Enemy powers that count *your* plays, in red: Withering Presence (every 6 cards you play adds a Wither to your hand).
- **Not in the tray:** Pael's Tears and Pael's Eye (crossed tabs on the cards that would give them up), and one-shot relics (Vambrace, Pael's Legion, Throwing Axe, Burning Sticks, Unsettling Lamp, Permafrost, Music Box: tabs on the cards that would use them; the game shows Pael's Legion's cooldown on the relic).

Thresholds are read live from each relic, so balance patches are picked up automatically.

**Game UI touched:** none; the tray is our own overlay. The relic bar's own counters are unchanged.

Checked against every relic the game gives a counter (v0.111.0): the rest are run-level counters (teas, Girya, Winged Boots, Toy Box...), plus Pael's Legion (block cooldown) and Pael's Flesh (shows the turn number).

## Incoming Damage

**What you see**, during your turn: a small stacked sum, read like a math problem. It uses the game's own intent icons: defend, and the attack icon tier that matches the incoming total (the same thresholds enemies use: under 5, 10, 20, 40, and 40+):

```
[eye]   +1 turn  only when ending your turn now gives you another turn first (Pael's Eye, Extra Turn): its icon
[attack]  14     incoming damage
[defend] − 5     your block at end of turn
[osty]   − 4     what Osty absorbs (Necrobinder, only while Osty is out; red if it dies)
──────────
      =   9     what gets through your block (red), or 0 in green
[heart]  + 3    only with HP loss no block stops (Regret, Beckon, Bad Luck): what it takes, on its own line so it never reads as block you're short of
[fairy]  31 HP  only when Fairy in a Bottle or Lizard Tail keeps you alive: its icon, and your HP after the enemy turn
```

Beside the last number (the heart line when there is one): a skull when this might kill you, with the chance when a roll decides it, and ? when some outcome has something not modelled, or while the numbers shown are waiting on a newer result for more than 100 ms (decision #107: on a busy board the last forecast stays on screen until the new one is in, and the ? says so; shorter waits show no mark, so it doesn't blink). When the search for every outcome stops at its memory or work cap (decision #107, rare), a lone ? replaces the numbers: no damage and no skull, nothing promised either way. The skull and the chance come from the whole enemy turn, both lines together. With nothing blockable coming, only the heart line shows. Teammate Incoming Damage shows it the same way.

**Extra turns** (decision #40): when ending your turn now gives you another turn before the enemies act (the game's own `Hook.ShouldTakeExtraTurn`: Pael's Eye with nothing played this turn, Extra Turn), the top row shows the source's icon and `+1 turn`. The sum below is still the enemies' next turn, which comes after that one, and the block you gain at the end of this turn will be gone by then.

**Death and what prevents it:** the simulator tracks your HP. At 0, Fairy in a Bottle is used first (the game asks `ShouldDie` before `ShouldDieLate`), healing you from 0 to 30% of your max HP; then Lizard Tail (50%, once a run). The rest of the hit that took you to 0 is lost, and later hits still land. With nothing left, you die: the skull. The numbers are the worst branch. The skull shows whenever some outcome kills you. When a roll decides it, the chance sits left of the skull (`25%`; the Death chance setting). A search that stops at a cap (too many outcomes to finish, decision #107) shows a lone `?` instead of the numbers and the skull, and a result held while a newer one is worked out carries a `?` after 100 ms (decision #105); so does a forecast with an outcome the simulator doesn't model (decision #92). A teammate's revives aren't modelled.

**Placement:** it sits just left of your block indicator, at the left end of your HP bar, and follows your character. If that doesn't fit on screen (your character stands near the left edge), it drops below the HP bar and every row of power icons instead; wrapped rows are measured. Move it with F8, or middle-click to pin it to the screen instead.

**How the numbers are worked out:** by the [outcome simulator](#outcome-simulator): your end of turn, then the enemy turn hit by hit, in turn order. Random targets (Lightning, Juggernaut, Forgotten Soul, Parrying Shield) are explored as branches, and the numbers shown are the **worst branch for you**. With one enemy, or when every branch ends the same (two Lightning orbs and two enemies they each kill), the result is exact.
- **Osty** (Necrobinder): enemies never target Osty, but its Die For You power takes the part of an enemy attack that gets through *your* block (pets share your block), up to Osty's HP; the overkill comes back to you. Damage that isn't an attack (Burn, Constrict, HP loss) isn't redirected. The Osty row uses Die For You's icon.
- **Your end-of-turn self damage** lands first, against your end-of-turn block.
- **Your end-of-turn damage to enemies** lands before they act, so an enemy it kills doesn't attack: Hailstorm (enough Frost orbs), The Bomb (last tick), Screaming Flagon (empty hand), Stone Calendar (its turn), Obsidian Vice (its damage per card in hand, one hit on a random enemy), Charon's Ashes (per Ethereal card exhausting), Inferno (each time you lose HP on your turn: Regret, Burn, Decay or other end-of-turn damage that gets through your block; unpowered, so enemy block takes it) and Glass orb passives (base value + Focus; the base drops by 1 each time it fires, never below 0, so a decayed Glass orb still deals your Focus) hit every enemy; Consuming Shadow's evoked orbs (one per stack, last orb first, after orb passives) hit the lowest-HP enemy (Dark, including this turn's growth) or every enemy (Glass); Lightning orb passives and evokes, Parrying Shield, Forgotten Soul and Juggernaut (once per end-of-turn block gain: Plating, each Frost passive trigger, Orichalcum, Cloak Clasp, Ripple Basin, each Feel No Pain exhaust, Consuming Shadow Frost evokes) hit a random enemy, so they're counted only when there's one enemy (with several, a kill we can't be sure of would hide an attack). Enemy block is still up at that point.
- **HP-loss effects**, in the game's order, on every hit that reaches your HP: Tungsten Rod (−1 each), Beating Remnant (caps HP lost per turn), then Buffer (cancels a hit, one charge each). Intangible is already in the enemy intent numbers.
- **Poison:** an enemy that Poison will kill doesn't attack. Every enemy's poison ticks as the enemies' turn starts, before any of them moves (`PoisonPower.AfterSideTurnStart`), so a poison death's reactions come first: Ravenous stuns the other Corpse Slug, Crab Rage hits harder. The amount is the game's own poison preview (`PoisonPower.CalculateTotalDamageNextTurn`), which already applies per-hit damage caps such as Exoskeleton's **Hard To Kill** (each instance capped, e.g. at 9). Skulking Colony's **Hardened Shell** caps an enemy's *total* HP loss per turn; the game's preview ignores that, so we apply it.
- **Doom doesn't stop attacks.** Doomed enemies die at the end of their own turn, after attacking.
- **Retaliation** can kill an attacker partway through a multi-hit. Each later hit is then cancelled, because the game checks for a dead attacker before every hit.
  - Thorns hits before each blow. The blow during which Thorns kills still lands.
  - Flame Barrier hits after each blow.
  - Reflect, after each blow, deals the damage you blocked.
  - Retaliation damage goes through the game's damage hook, so the enemy's caps and Vulnerable apply. It hits the enemy's block first; enemy block is assumed cleared at its turn start unless it has Barricade.
- **Unblockable HP loss** (Regret, Bad Luck, Beckon: anything the simulator lands as unblockable on you) is its own line under the result (the heart), not part of the incoming or the result: block does nothing to it. It's what you lose to it after the HP-loss effects (Tungsten Rod...), the worst outcome's.

**Sources:**
- **Blockable:** enemy attack intents (`AttackIntent.GetSingleDamage` × hits, the same numbers the game shows); Burn, Decay, Infection, Toxic, Wither in hand; the Constrict, Magic Bomb, Disintegration and Insatiable Dominion debuffs (Constrict and Magic Bomb only while the enemy that applied them lives). Each goes through the game's damage math on you, so Intangible makes it 1.
- **Unblockable:** Regret (HP loss = cards in hand), Bad Luck, Beckon; Demise on an enemy (Powdered Demise).
- **End-of-turn block** (the "block" line = current block + these):
  - Plating
  - Frost orb passives (times the game's passive trigger count, so trigger-boosting effects are included)
  - Frost orbs evoked by Consuming Shadow (their evoke block)
  - Orichalcum / Fake Orichalcum (only if you have 0 block when your turn starts ending: BeforeSideTurnEndVeryEarly, before Pael's Eye exhausts your hand)
  - Cloak Clasp (block × cards in hand)
  - Ripple Basin (only if you haven't played an attack this turn)
  - Feel No Pain × Ethereal cards still in hand: they exhaust at end of turn (after Orichalcum checks your block), each giving Feel No Pain's block (and setting off every other exhaust effect: Charon's Ashes, Forgotten Soul, Dark Embrace's draws and what they set off)
  - Each player's end-of-turn effects come in player order (a teammate before you acts first), and each source shows under the game's own name
  - Not counted: Horn Cleat and Captain's Wheel. They give block at the *start* of turn 2/3, after the enemy has attacked; Relic Counters shows their countdown.

**Wuppy** (event relic): while your pet Wuppy lives it takes every attack aimed at you, before your block, so those hits aren't in your Incoming Damage (your Flame Barrier and Reflect don't react to them; your Thorns still does, since you're still the attack's target). A hit bigger than Wuppy's HP kills it and the rest of that hit goes on to your block and you, as do the hits after it. A teammate's Wuppy does the same for them.

**A teammate's (multiplayer, Teammate Incoming Damage, its own setting and widget):** hovering a teammate (the game then shows their HP bar, `NCreature.OnFocus`, read through `NCreature.IsFocused`) shows the same sum for them, just left of their block indicator. It comes from the same simulation as yours, which leaves out the cards in their hand (decisions #25, #38): their hand size counts (Cloak Clasp), the cards in it (Burn, Regret, Ethereal cards that exhaust) don't, unless **Count teammates' hands** is on. Their block, powers, orbs, relics, potions (Fairy in a Bottle) and Osty count as yours do: every player takes the enemy turn through the same simulation (decision #93). HP loss no block stops is its own heart line, as on yours. With the setting off, anything their hand would change at the end of turn (their Ethereal exhausts, Regret) isn't in what's shown: a lethal tab, the Death Skull or a number can be off then (decision #94). The forecast check compares their HP (overkill included, as yours) and their Osty's against it every enemy turn, always with their hand.

**Game UI touched:** none; our own widget.

**Game UI read (not changed):** the player's `NCreature` → `%HealthBar` (`NCreatureStateDisplay`) → its `%HealthBar` (and that bar's `%BlockContainer`) and `%PowerContainer`'s icons, for placement only.

**Not yet:**
- Health-bar preview.

## Proc Indicators

**What you see:** on each card in your hand, a tab for every power or relic that playing it would set off right now, with that source's icon (see "On-card tabs").

**How it's worked out (1.0.0, decisions #48, #49):** the card's play is simulated once per target by the [outcome simulator](#outcome-simulator). Every power and relic that acts on plays, hits, block, powers landing or card events is a model of its game hook, and it logs what it did. A tab shows when its model fired during the play: in every branch for some aim (plain), or in some branch for any aim (crossed). A power the card itself gives you counts too when it fires on that same play (Pale Blue Dot as your 5th card this turn). Effects that play off each other chain on their own: a draw from Dark Embrace sets off Speedster, The Sealed Throne's stars set off Black Hole, Kunai's Dexterity counts for the block that comes after it.

**When it's worked out (decision #114):** only when something changed: the board as the simulator reads it, the fight or turn, the tab settings, or a card in hand (its numbers, cost, keywords, affliction, plays, or whether it can be played). While nothing has, and every result is in, the last frame's tabs stay. Where you aim never matters: a tab that needs aim is worked out for every target.

- **Plain tab:** it triggers (draws, energy, Strength, channels, upgrades, creates cards...).
- **Tab with a number:** it gains you block, deals damage, or summons, and the number is how much. Block uses the game's own block math (`Hook.ModifyBlock`), so Dexterity and Frail count where they apply. Block and damage are what the simulated play gained or dealt in total (every enemy hit, each through its own modifiers), the most that some aim guarantees.
- **Crossed tab:** it helps the enemy or hurts you; a number is the damage you take.
- **Multiplied by plays:** a card that plays twice (Echo Form, Burst...) sets off per-play procs twice. Procs that fire once per card (Black Hole, stars spent, exhausting itself) count once.
- **Indirect procs** (setting `ProcIndirect`): cards that exhaust or discard other cards, draw, or create cards count what those set off too, through the whole chain (what a drawn-card proc sets off in turn counts as well). For example, with Feel No Pain, True Grit shows the block from exhausting another card. Choices you make mid-play count as the most the card can do (Purity, Hidden Daggers).
- **Counter relics** (Kunai, Shuriken, Ornamental Fan, Nunchaku, Kusarigama, Letter Opener, Tuning Fork, Iron Club) show only on cards that complete the count; the tray shows progress.
- Several enemies with the same power share one tab, amounts added.
- **Teammates' sources** (decision #75): a teammate's powers and relics are sources too, so what your card sets off for them gets a tab like your own (their icon; plain or crossed by the same rule). A source you and a teammate both have shares one tab, amounts added. The simulator logs a teammate's firings under their id (`Name@id`), so theirs never count as yours. The proc audit watches every player's relics and powers.
- Cards that can't be played (Unplayable, blocked, or their own condition unmet, via `CardModel.CanPlay`) get no proc tabs. Cards you can't afford yet still show them, since energy can come mid-turn.

**Uses or breaks a relic** (formerly Relic Reminders): Pen Nib ready (attacks); crossed Art of War / Ripple Basin (attacks, until you've played one this turn); crossed Pael's Tears (cards that would leave you with no energy once the play has resolved, since the relic only checks at the end of your turn: energy the play gets back first leaves you some, from the card itself (Production, Turbo and every card that gains energy when played, read from its code; Sunder on a kill, Bow Smack on an impaled target, Restlessness as your only card, Forgotten Ritual after an exhaust this turn, Double Energy, Mad Science's Energized rider, Epic Retrieval per arrow it knocks loose; Sown on its first play) or from what it sets off: Orbit, Automation, Subroutine, Yah, Ivory Tile, Nunchaku. Decision #117); crossed Pael's Eye (every card, while armed and nothing played this turn: playing one gives up the extra turn); one-shot Vambrace (block cards), Pael's Legion (block cards while it's off cooldown: double block; both only when the card's block is above 0 after the game's math: not under No Block (Panic Button), negative Dexterity or anything else that zeroes it, Entrench with no block, and only the first play of a replayed card; Adroit's block counts, so an Adroit attack gets them too), Burning Sticks (skills that exhaust when played), Unsettling Lamp (debuffing cards, temporary debuffs like Dark Shackles included, when some enemy you could debuff has fewer Artifact charges than the debuffs this play applies: the lamp ignores debuffs that Artifact blocks; the predictions double that play's Strength loss and poison), Music Box (attacks).

**Your attack against enemies** (from the card's damage to each enemy, through the game's damage math, times its hits, vs that enemy's block and HP). Hits match each card's own code: its hit count (HitCount from game v0.113.0; Repeat or a fixed count like Twin Strike's before), Whirlwind's X, a calculated count (Finisher, Flechettes...), or a condition (Dismantle on a Vulnerable enemy, Spite after you lost HP this turn, Fiend Fire per other card in hand), then the game's hit-count modifiers (Thumbscrew: one more on multi-hit attacks), as the card's own preview applies them. The Fool's cards: a Shoot card with no arrow to shoot does nothing (no damage counted); Nail hits only an Impaled enemy; Wah Blast hits twice once you've played a Cho or a Ki this turn. Damage goes through the game's math with the card's own damage properties, so arrow attacks get Aim (doubled by Heavy Shot), Dislike You and Quietus; on an enemy only your arrows Impale, hits after the one that knocks your last arrow out lose Serrated Arrows' and Wah Hammer's bonus. A replayed single-target card that makes its target Vulnerable (Break: the hit, then Vulnerable) hits its later plays with Vulnerable's multiplier (Paper Phrog, Cruelty and Debilitate included) when the target wasn't Vulnerable and has no Artifact. A replayed shot at an enemy that isn't Impaled impales it with its first play, so its later plays get Serrated Arrows' bonus (an arrow for each play, at most 3 hits a play, no Quietus). Rain Shot then deals its damage to every other enemy. A card that gains its block more than once (Cho Limbs, Cho Firm with an arrow, Second Wind per card) counts each gain in full:
- Thorns on an enemy: **crossed**, damage to you per hit. Personal Hive (Dazed into your deck): **crossed**. Curl Up and Skittish (it gains block): **crossed** when the [outcome simulator](#outcome-simulator) says this play makes it gain block in some branch (Curl Up: a card's attack hits it; Skittish: an attack gets through its block, once per turn).
- Asleep / Slumber (wakes it): **crossed**. Each damage instance that gets through its block counts (Asleep wakes on the first, Slumber after its Amount). Judged by the [outcome simulator](#outcome-simulator) through the end of your turn: the card's hits, orbs it evokes, procs it sets off, then your end-of-turn damage (the enemy's block stays up until its own turn). A warning, so it shows when waking is **possible** in some branch after this card and isn't without it.
- From the [outcome simulator](#outcome-simulator), through the end of your turn: Burrowed (breaking its block stuns it), Flutter (enough of your attack's hits getting through stun it), Plow and Shriek (damage through that leaves it at or below their amount stuns it): plain when it's stunned in every branch for some aim and isn't without this card. The Gambit (an attack getting through kills it): plain, every branch. Slippery (each hit loses it at most 1 HP): crossed when this card makes it use a charge in any branch.
- **Imbalanced** (Bowlbug and others; fully blocking one of its hits stuns it or knocks it off balance): a plain tab when, after this card, its first hit is fully blocked in **every** branch of the [outcome simulator](#outcome-simulator) and it isn't when you end your turn now. The card's block, Frost orbs it evokes, block procs and your end-of-turn block all count.
- Random and all-enemy proc damage (Kusarigama, Letter Opener...) lands after the card, so enemies the card kills aren't targets; a play that kills every enemy (one that revives keeps the fight going) gets no such tab.
- Killing an enemy, from the [outcome simulator](#outcome-simulator)'s kills during the play (the card's hits, orbs it evokes, procs, Juggernaut; random targets as branches): Gremlin Horn (energy and a draw) when some enemy dies in every branch for some aim; crossed for enemy death effects when that enemy (Infested, Steam Eruption, Surprise, Explosive, Stock while it has stock left: a new Axebot takes its place and attacks) or another one (Crab Rage, Ravenous) dies in any branch. Kills count damage from orbs the card evokes, not just its attack: channelling into full slots evokes your front orb first, Dualcast / Quadcast / Multicast evoke it several times, Shatter evokes every orb twice. Glass hits every enemy, Dark the lowest-HP one, Lightning a random one (counted only when there's one enemy). Orbs a play channels and then evokes itself aren't counted.
- Breaking block: Hand Drill (Vulnerable), when the simulator says the play breaks some enemy's block in every branch for some aim (its hits, orbs, procs, Juggernaut).
- Parrying Shield (end of turn: 6 damage to a random enemy when your block is at least 10), from the [outcome simulator](#outcome-simulator) before and after the play: plain when the play makes it fire in every branch and it wouldn't for sure now; crossed when it would for sure now and the play can stop it (Orichalcum no longer arming, less block after a Burn, Thorns). With Gorget's Plating 4 and Orichalcum 6 on turn one, one Defend crosses it and a second makes it plain again. It fires after the play, so the proc check doesn't expect it during the play (it never flashes); the forecast check covers its damage.

**Losing HP during the play** (the card's own HP cost, Bloodletting-style, and enemy Thorns hitting you back before each of its hits), from the simulator: your block, Tungsten Rod, Beating Remnant and Buffer apply in the game's order, so a tab shows only when the play really sets the relic off (in every branch, for some aim). Tungsten Rod (whenever some gets past your block: it takes 1 off), and when you actually lose HP: Centennial Puzzle (first time each combat), Self-Forming Clay, Demon Tongue (first time each turn), Emotion Chip, Red Skull (when it takes you to its threshold), Rupture, and Inferno (its damage to every enemy, each time). The crossed Thorns tab stays on every attack that can hit a Thorns enemy, blocked or not.

**Sovereign Blade:** the powers buffing it show as tabs on the Blade: Seeking Edge (hits all enemies), Parry (gains block), Sword Sage (replays), Conqueror on an enemy (anyone's: double Blade damage to it).

## Outcome simulator

**While a play resolves (decision #28):** tabs, Incoming Damage and the Death Skull show the board as it is, mid-play included; they don't run plays still resolving or queued (a teammate's can't always be seen). They settle once the play finishes. The proc audit doesn't use them: it checks each play against a prediction made as that play begins.

One simulator behind Incoming Damage, every proc tab, the lethal tab, the Imbalanced and wake tabs, and the audits (`mods/SpireQoL/Sim/`; design: docs/SIMULATOR_V2.md, decisions #48, #49). A card play is a script of actions (its HP cost, attack, block, powers, card events) run once per play between the game's `BeforeCardPlayed` and `AfterCardPlayed`. Relics, powers and enemy effects are models of their game hooks, called in the game's listener order. Each hit's damage and each block gain are worked out when they land, through the game's pipelines: terms from models for sources that change during a turn (Strength, Vigor, Vulnerable, Pen Nib, Tender...), and terms read from the game for the rest. The damage-formula audit compares each card's simulated first hit with the game's preview. It has no game types, so it's tested without the game (`tests/SpireQoL.Sim.Tests`, run on every push by the "Simulator tests" workflow).

- **State** (`SimAdapter.Build`): each enemy's HP, block, Hardened Shell budget, Hard to Kill / Intangible cap per hit, poison (its next tick's damage, its stacks and how many times it ticks), Barricade, stun, Imbalanced, its reactions to your plays (Curl Up, Sneaky, Skittish), what being hit does to it (Burrowed: keeps its block between turns and is stunned when it's broken; Flutter: stunned after enough attack hits get through; Plow and Shriek: stunned at an HP threshold; The Gambit: killed by an attack getting through; Slippery: at most 1 HP lost per hit while it has charges; Slumber: each hit through its block takes a stack, the last wakes it stunned; Thorns: hits you, blockable, before each hit of your card's attack, so your block left for its turn goes down), how it reacts to an ally dying (Ravenous: stunned; Crab Rage: its attack with the Strength and its block, once), Explosive (its death damages every living player, blockable, through the game's damage math per player, wherever it dies: your card, your end of turn, its poison tick), and its attack (the intent's numbers per hit); your block, the powers and relics that act at end of turn (Juggernaut, Plating, Feel No Pain, Hailstorm, The Bomb, Consuming Shadow, Thorns (Cho Barbs' temporary Thorns is already part of it, so it counts once), Flame Barrier, Reflect, Buffer, Envenom, Concoct; Snecko Skull, The Boot (your attack hits that lose an enemy HP lose it at least its minimum, after Hardened Shell and Slippery), Orichalcum, Cloak Clasp, Ripple Basin, Screaming Flagon, Stone Calendar, Charon's Ashes, Forgotten Soul, Parrying Shield, Lunar Pastry with Black Hole, Pael's Eye, Insatiable Dominion, Inferno (yours; a teammate's isn't modelled), Tungsten Rod, Beating Remnant), your draw and discard piles by profile (decision #90: what about each card matters if you draw it now; never their order),
 your end-of-turn auto-plays (Stampede and Simpleton with the cards in your hand they can pick, Howl from Beyond in your exhaust pile, I Am Invincible when every card in your draw pile is a copy of it, so it's certainly on top), cards in hand that act at end of turn, Ethereal cards that will exhaust (those Ethereal only through Hex don't once the enemy that cast it is dead: Hex goes with its caster, and so does their Ethereal), orbs in order with their values and passive trigger counts, and Osty.
- **A card play** (`SimAdapter.Play`): its hits (per target, through the game's damage math), its own block (Rally's to every living player too, worked out on each: `AllPlayersBlockCards`, decision #75; teammates' draws and created cards are their own card events, for their procs: Huddle Up's draws for each teammate up to their hand's room, `TeammatesDrawCards`, Blade Symphony's Shivs created by each teammate, `TeammatesShivCards`, Constellation's draws for its target; Glimpse Beyond's Souls are created by you, once per Soul per teammate; Fisticuffs' from the damage it deals, through Dexterity and Frail; and its Adroit enchantment's, on every play; Stretch boosts Adroit's block on any card, and a replay's later plays gain it without the Stretch, Pael's Legion or Vambrace the first play spent), orbs it evokes and channels (channelling into full slots evokes the front orb first; new orbs get your Focus; Chill channels one Frost per enemy, Spinner channels on play only when upgraded), powers it gives you (Plating, Juggernaut, Feel No Pain, Thorns, Flame Barrier; from the card's power value, or the plain value its code applies: Feel No Pain's, Flame Barrier's), poison it applies (plus Snecko Skull's 1 per application; added stacks raise the tick by the game's formula, so Accelerant's extra ticks count: 1 tick plus every living player's Accelerant, teammates' included, and Accelerant you play raises every enemy's ticks), Outbreak setting off every enemy's poison during the play (a hit per tick for the stacks then, a stack less after each), Envenom's poison on each of its hits that gets through block, Focus it gives or takes (Defragment, Biased Cognition, Hotfix, Focused Strike, Synchronize; Hyperbeam's Focus loss), which moves your orbs' values with it (from each orb's base, so other modifiers stay), orb slots it adds or removes (Capacitor and Modded add, up to 10; Bulk Up removes one, dropping your back orb without evoking it; a character without orb slots gets one on their first channel), Thunder hitting a Lightning evoke's target again, Expose taking all of its target's block (Burrowed reacts) and its Artifact before its Vulnerable, Echoing Slash hitting every enemy again for each one a round killed, Osty killed by your card (Sacrifice, Bone Shards: his share of the hits comes to you), teammates in multiplayer as full players in the same simulation (decisions #24, #25): cards aimed at a teammate (one simulation per teammate, like an attack aimed at any enemy; what lands on them goes to them, never to you: Lift's, Constellation's and Demonic Shield's block, Ignition's Plasma into their orbs, evoking their front orb when full; Mimic's block from theirs; Constellation's draws are theirs; Intercept moves the powered attacks on them onto you: theirs × 0, yours × (players you cover + 1), from the game's damage math; the cards that only buff them or hand them cards (Self Deprecate's Joy) are reviewed in `CardCoverage`), their end-of-turn effects (orbs in player order, Hailstorm, The Bomb, Stone Calendar, Consuming Shadow; their Ethereal cards exhausting: Feel No Pain, Charon's Ashes, Forgotten Soul, which depend on their hand, so they count in what's shown only with **Count teammates' hands**), their block (Plating, Orichalcum, Frost) and HP, each enemy hit landing on every living player in player order with that player's own amount (the game's damage math per target: Vulnerable, Intangible, Tank, Covered...), their Thorns, Flame Barrier and Reflect (which can kill an attacker before its next hit on you), Buffer and Tungsten Rod, Beacon of Hope sharing half of a block gain with every other player (one hop, as the game does), Juggernaut on their block gains, and Weak or Strength your card applies changing their hits too, poison on random enemies (Bouncing Flask: a branch per target each time), intents it changes (Weak on an enemy that isn't Weak and has no Artifact; Surrounded (Kaiser Crab): a card aimed at the crab behind you turns you to face it, so the other one's attack becomes the 50% stronger back attack, and killing one crab turns you to face the one left, which no longer back-attacks: recomputed with the game's damage math), the enemies' reactions once it's played (Curl Up's block after a card's attack hits it, Sneaky's block after each Attack, Skittish's block when an attack gets through, all before your relic procs land), an attack whose damage changes during its own plays, each hit from the game's damage math for its play and the Strength gained so far: Tender (1 Strength and Dexterity less after every play, so a replay hits and blocks 1 less each later play), Pen Nib (it doubles only the play that brings its count to 10, so a replay's other plays aren't doubled) and Mighty Wings (its Strength from a hit of 30 or more lands before the attack's next hit), its own HP cost (unblockable, before its hits, through Tungsten Rod, Beating Remnant and Buffer, setting off Inferno), the cards it draws or creates (Impatience draws only with no Attack in your hand, Fetch only on its first play each turn while Osty is alive; and a Make It So it brings back to your hand on every 3rd Skill), Covering Fire's block for every teammate on each shot you try (with or without an arrow; Repeat Shot at X 0 tries none), and the damage and block procs the proc rules predict for it.
- **Order** (`SimEngine`, from `CombatManager.DoTurnEnd` and the hook order): the play, then the auto-play phase (every player's, in player order, before the rest of the end of turn; a teammate's Howl from Beyond and I Am Invincible count, their Stampede and Simpleton don't, since those pick from their hand: Stampede plays a random Attack from your hand and Simpleton a random card among your cheapest, each a branch, aimed at a random hittable enemy when it needs one; then I Am Invincible's block and Howl from Beyond's attack; auto-played cards cost nothing and count as attacks played for their owner's Ripple Basin; a card played from the exhaust pile doesn't leave the hand, so Cloak Clasp counts the hand as it was; a pick that changes your hand, by drawing or making cards, still plays and its hits count; only later picks in that branch, from the changed hand, aren't predicted), then your end of turn: Pael's Eye exhausting your whole hand when you've played no card this turn (each card sets off Feel No Pain, Charon's Ashes and Forgotten Soul, and none is left to act in hand), Orichalcum's check (you had no block), Plating, your powers (Hailstorm, The Bomb) before your relics (Orichalcum, Cloak Clasp, Ripple Basin, Screaming Flagon, Stone Calendar), orb passives front first (Gold-Plated Cables' extra trigger goes to whichever orb is in front; a Glass orb's base value drops by 1 each time its passive fires, Focus adds on top, and its evoke is twice its current passive), Ethereal cards exhausting (Feel No Pain, Charon's Ashes, Forgotten Soul), then cards in hand in hand order (Burn, Regret...), then your powers in order (Constrict, Magic Bomb, Demise, Consuming Shadow evokes), your relics in relic order (Lunar Pastry's stars setting off Black Hole on every enemy, Parrying Shield), then Disintegration and Insatiable Dominion (2 + your turn number to you, blockable). Then the enemy turn: poison tick, block cleared unless Barricade, each hit with your Thorns, block, Osty, HP-loss effects (Tungsten Rod, Beating Remnant, whose budget carries over from your turn and isn't spent by hits Buffer stops, Buffer), Flame Barrier, Reflect. Every block gain sets off Juggernaut. "Dead before it acts" (lethal) means dead by the end of your turn or by its own poison tick, not killed by retaliation during its attack.
- **Random targets** are explored: one branch per possible target, with enemies killed earlier no longer targets. Branches that end up identical are merged. Every outcome is explored in one search that advances every branch one step at a time and merges identical branches after each step (decision #107), so many random hits cost as many branches as there are distinct results (ten Lightning orbs on three enemies: 66 branches, not 59,049 orders), and the chances are exact: a branch's share of the rolls is the number of orders that lead to it.
- **Good outcomes need every branch; bad ones need only one.** Lethal and Imbalanced show only when they happen in every branch; wake warnings show when they happen in any branch; Incoming Damage shows the worst branch.
- **Lethal tab** (`lethal`, the skull; with the aim marker when only some targets are lethal): after playing this card (aimed at any one enemy, for single-target cards), some enemy is dead before it acts in every branch, and ending your turn now wouldn't kill it. When a roll decides it (decision #88), the tab carries the chance in its number corner (`50%`; `40%?` when a search stopped at a cap or met something not modelled, counting only the deaths it settled), shown when the card surely makes that enemy's death more likely: its lowest chance beats the highest ending the turn now could give. The Death chance setting turns these off (certain kills only). That counts the card's hits, orbs, procs, and everything your end of turn does: Stone Armor with Juggernaut (Plating's block at end of turn sets off Juggernaut), the Juggernaut card with Orichalcum and no block, poison that kills it at the start of its turn.
- **Knowable information only:** it reads what the game shows and the game's rules; random targets are branched, never read from the RNG.
- **Draws (decision #90):** your draws come from your draw pile. Each card there gets a profile of what matters if you draw it on this board: acting in hand at end of turn (Burn, Regret), exhausting as Ethereal (Feel No Pain, Charon's Ashes), a Status with Iteration, Ethereal with Pagestorm, a Strike with Hellraiser, and with Stampede or Simpleton the card itself; everything else is one plain profile. A draw branches once per profile, weighted by how many cards have it (each card equally likely: the order is hidden), so a pile where nothing matters doesn't branch at all, and Burn and an Ethereal Burn stay apart when Feel No Pain makes them differ. The card joins your hand: it acts at end of turn, exhausts if Ethereal, Stampede or Simpleton can pick it. None into a full hand (10; the card being played has already left it), the card staying in the pile (`CardPileCmd.Draw`); a card *made* into a full hand goes to the discard pile instead (`CardPileCmd.Add`), so your hand size never counts past 10; the discard pile shuffles in when the draw pile is empty. Each draw's reactions come before the next: the draw reactions (Speedster, Corrosive Wave, Automation, Cacophony) and the draws they chain (Iteration on the first Status drawn this turn, Pagestorm on each Ethereal card), so with the hand nearly full the order is the game's. A Strike drawn with Hellraiser is auto-played by the game, which isn't simulated: later auto-plays aren't predicted then. A teammate's draws are only counted. **Cards that act on what they draw (decision #118):** Escape Plan gains its block only when the card it draws is a Skill, Pillage draws again while it draws an Attack (until your hand is full), Scrape discards the cards it draws unless they cost 0 (a discarded Burn no longer burns you; a discarded Sly card plays itself, which isn't simulated: `?`). While one is in your hand, the profiles also carry each card's type or whether it costs 0, so each outcome has its exact chance. **The known top (decision #91):** cards the game placed on top of your draw pile (Headbutt, Thinking Ahead, Recall, Glimmer, Ki Chant, a card played back to the top) are remembered in order (the last placed is on top) until they leave the pile, and drawn first, for certain. A card shuffled in at a random place, or a shuffle (`CardPileCmd.Shuffle`: your discard pile and the rest of your draw pile, as Reboot does), forgets them; after a shuffle, the one card enchanted with Perfect Fit is on top (with several, which is on top isn't known). **I Am Invincible** plays itself from the top of your draw pile as your turn ends: certain when it's known to be on top, else a chance (how many copies are in the rest), and its block counts in that share of outcomes. A diagnostic check compares the known top with the pile's real top and logs (`[audit] [draws]`) and forgets it on a mismatch, so a source we missed shows in the logs, not in a prediction.
- **Speed:** simulations rerun only when something in the state changes (results are cached by a fingerprint of the whole state, intents and powers included). Each frame reads the game and builds every card's play on the main thread, then runs all the cards' simulations (one per target) in parallel across CPU cores and waits for them, so tabs usually appear on the frame they belong to. A typical hand takes well under a millisecond. **The frame waits 8 ms at most (decision #104)**, shared by the turn forecast and every card, and for each simulation only on the first frame it's asked for: what isn't ready by then is left to the background and shows when it is, a frame or a few later. **Until then, what was on screen stays (decision #105):** a card whose simulation (or the turn forecast) has no result for the new board keeps the tabs it showed from its last result this turn, and Incoming Damage, the Death Skull and Teammate Incoming Damage keep this turn's last forecast, so nothing blinks out on each hit of a busy play. Each card switches as soon as its own result is in (an enemy dropping into lethal range after a hit shows as soon as that card's simulation has caught up); only a storm of hits faster than the simulations leaves them a few frames behind. Nothing is held across turns or fights, and the audits never use held results. The combat summary logs the waits (`[perf] combat summary: simulations`: how many, the average and longest, how many were left to the background). A simulation's work is bounded by two caps (decision #107) and tested by counting it (state copies and states held, not time). **Not modelled (decision #92):** where a branch meets something the simulator doesn't model yet (an end-of-turn auto-play from a hand it lost track of, an auto-played card whose play isn't built, Hellraiser playing a drawn Strike), the branch carries the reason and counts as unknown in every chance: what's shown carries the `?` and a range. An enemy's death that already happened in it still counts. The audits count the reasons. A card played while its simulation had stopped at a cap, or with a branch not modelled, has its proc tabs (procs, their block and damage) left unchecked, counted as skipped: what happened may be an outcome that wasn't worked out. The state after the play is still checked (the audit runs its own simulation).
**Searching every outcome (decision #107):** each simulation is one search on a worker thread. Every step (a hit, an orb, a block gain, a draw) advances every branch together, and branches that reach the same state merge, adding their shares of the rolls: the work grows with the distinct states, not with the orders of random targets, and nothing is sampled or dropped. The frame waits a few milliseconds for it at most (above); a search that takes longer goes on in the background (after its first 20,000 state copies it waits for a turn, half the CPU cores at most) and its result shows once it's over; until then the last result stays on screen. A new board cancels it; the forecast check keeps its frozen forecast's search going and compares with all of it. Two caps stop a search: **memory**, 150,000 states held by every search together (about 2 KB each), past which a search holding at least an eighth of that stops; and **work**, 3 million state copies for one search (a chain inside one step that branches on every branch, like Beacon of Hope sharing block with Juggernaut on three or four players, holds little but runs on). A stopped search keeps the branches where it stopped, every share of the rolls with them: what's settled there still counts (an enemy already dead: its death chance shows as a range from that floor, a lethal tab as "75%?"), the play's own results are exact when the play was over before the cap, and everything else is unknown (Incoming Damage shows a lone ?). Every cap hit is logged (`[sim] cap:` which cap, steps, copies, states held, time), counted in the combat summary (`[perf] combat summary: searches stopped by`), and sent as an error report (`sim-cap`, decision #105: one per cap and kind, the turn forecast or a card's play, with the card as a tag and the start state to replay). Searches that went to the background are logged (`[sim] searched`: steps, copies, states held, outcomes, time). The combat summary also counts the frames shown with held tabs or a held forecast. Branches share their orbs and teammates until one changes them (decision #23).
- Approximations: orb values of newly channelled orbs use base values plus Focus and Infused Core; a card's procs all land after its hits; added poison ignores damage modifiers on its tick; Skittish reacts once to all of a replayed card's hits; a card's block split across several gains drops the remainder; random card draws and random orb types (Chaos) aren't simulated beyond their count; auto-played cards get no procs from the proc rules (their hits, block, orbs and powers count). Enemies that revive (Test Subject, Illusion, Decimillipede segments) spend their turn reviving, so their kill holds for the turn; the simulator never ends the fight early.

## Shuffle Warning

**What you see:** a **discard pile** tab (the game's own discard pile icon) on cards in your hand whose draws are more than your draw pile (with cards in your discard pile), so playing them reshuffles your discard pile mid-turn. Reboot, which always shuffles (its text says so), gets no tab, but its shuffle counts for shuffle procs (Biiig Hug). Ki Chant, which shuffles when your draw pile is short of what it looks at (its text says so), gets none either; played several times, a later play finding the pile short counts too. Draws after Ki Chant (Motif) count the cards it took off the draw pile and the one it put into your hand. Nothing else: you know what a reshuffle means for the cards in your hand.

**Draws counted** (`PlayFacts.Draws`): the card's own draws plus the draws it sets off: Dark Embrace (its amount per card exhausted, so Burning Pact with Dark Embrace draws 3), Joss Paper (reaching its exhaust count), Game Piece (a Power), Iron Club (completing its count; it draws after your powers react to the play, so cards Calamity adds to your hand first can fill it), Vicious (per Vulnerable you apply), Centennial Puzzle (first HP loss), Motif (its amount per Wah, Cho or Ki the card plays first this turn, after the play). Draws stop at a full hand (10, counting the cards it exhausts from hand first), and No Draw or Fiddle blocks them all. Cleanse's exhaust from the draw pile shrinks it first. Calculated Gamble discards the rest of your hand before drawing that many, so those cards can be shuffled back in even from an empty discard pile. With Biiig Hug, the Soot a shuffle adds counts as a created status (Smokestack, Trash to Treasure). Draws that depend on which card comes up (Pagestorm, Iteration) can't be known (the draw order is hidden) and aren't counted. The same count feeds every draw-based proc (Automation, Cacophony, Speedster, Corrosive Wave) and the shuffle procs (Stratagem, The Abacus, Biiig Hug).

Draw cards are every `CardPileCmd.Draw` caller in the decompile (TRACKER §6). Most draw their Cards amount; Dagger Throw, Escape Plan and Pillage draw one (Pillage at least one); Scrawl draws up to a full hand; Compile Driver draws one per distinct orb type (the card's own calculation); Restlessness draws only when it's the only card in hand; FTL draws only while you've played fewer than 3 cards this turn; Mad Science draws only with the Wisdom rider; Ki Hop draws on each play that starts with its target Impaled (its own hit can knock the last arrow loose, so a replay may not draw), and Wrest draws only on its first play (it pulls all your arrows out); counted for the worst target you could aim at. A card that plays twice draws twice. The discard pile icon is read from the live discard pile button (`NCombatUi.DiscardPile` → `Icon`).

## Death Skull

**What you see:** during your turn, the game's skull (emote wheel) just left of an enemy's HP numbers (a small gap between them, scaled to the numbers) when it dies before acting if you end your turn now: poison, end-of-turn damage, your orbs and your teammates' (see [Outcome simulator](#outcome-simulator)). When a roll decides it (a random Lightning target with several enemies), the skull carries the chance, e.g. `50%`: each random target equally likely, from the simulator's branches weighted by their share of the rolls. When a search stops at a cap (decision #107), it shows the deaths settled before the cap as a range with a `?` (`40–55%?`: those deaths, up to that plus every outcome not reached). The card's lethal tab still means "this card makes the kill more likely"; this shows the deaths that happen anyway (decision #73).

**Settings:** the `death-skull` switch; **Death chance** (General, on by default) shows or hides the chance (off: only certain deaths).

**Game UI touched:** adds a skull (and the chance) as a child of each enemy's HP label (`NHealthBar` `%HpLabel`); the game's label isn't changed. No Harmony patches.

## Intent Forecast

**What you see** (decisions #72, #73), during your turn, while you hover an enemy's intent (the intent icons, not the enemy): a backdrop-free stack right above the intent (a certain turn's intents centred over the intent on screen with its power icons to the right, kept level with the intent icon in their row as it bobs; the widget is frameless while locked) (beside it, to the right, when there's no room above; a movable widget) with its next moves after the intent on screen, a row per move stacked upward (`+1` nearest the intent, later turns higher; a random pick's moves at the top), each drawn with the game's own intent node (`NIntent`: the icon, its animation, bobbing in step with the intent on screen, and its damage number, worked out as things stand now):
- **What a move applies:** small in the bottom-right corner of the buff or debuff intent it belongs to (as on the intent on screen: `Features/IntentCorner`, decision #99), each power the move applies, with its icon and amount (Frail 2), read from the move's own code (`Sim/Adapter/MovePowers`: its `PowerCmd.Apply` calls, and the amount passed in when it's a constant or a number the enemy keeps, read now, ascension included; the icon alone when the amount is worked out some other way). `IntentRulesTests` checks every buff and debuff move in the game names its powers.
- One row per turn, upward: the row just above the intent on screen is the turn after it, the next row up the one after (no turn numbers: the order says it). Every turn its move rules make certain is shown, up to three turns ahead.
- The first random pick ends the forecast: its moves side by side on one row, each with its chance above it (`45%`), so it stands apart from the certain turns below it.
- Nothing while its intent on screen is hidden (`HiddenIntent`, `UnknownIntent`): its rules would give the hidden move away. A future move whose intent is hidden shows hidden, as the game would.

**How it's worked out** (`Sim/IntentForecast`, pure and tested; `Sim/Adapter/IntentReader` reads the game): from the enemy's move rules (`MonsterMoveStateMachine`), the way the game picks its next move when the current one ends (`FindNextMoveState`): a move goes to its follow-up (the initial state when it has none); a random branch (`RandomBranchState`) picks by weight, a branch weighted 0 by its repeat rule never picked (`GetStateWeight`: `UseOnlyOnce` after its first use, `CannotRepeat` and `CanRepeatXTimes` after that many in a row, a cooldown over the last moves); a conditional branch (`ConditionalBranchState`) takes the first branch whose condition holds now. Weights and conditions are the game's own lambdas, read as things stand (an HP threshold, an ally's death, a counter): the forecast is "if nothing changes before the roll". A stunned enemy makes the move it lost next (`Creature.StunInternal`). It reads the moves the enemy has made this fight (`StateLog`), never the RNG: the turn after the intent on screen hasn't been rolled. A weight or condition that can't be read only stops the forecast where it's reached. Four enemies set moves outside their rules (Queen, Test Subject, Tough Egg, Waterfall Giant: `SetMoveImmediate`), which the forecast can't see.

**Checked** (`IntentForecastAudit`): each time the game rolls an enemy's next move, the forecast for that roll is worked out from the state at that moment and compared with the move it picked: a certain forecast must match, a random one must have given it a chance above 0; every roll is logged with its odds (`[audit] [intent]`). The catalog tests read every enemy's move rules in the installed game (`IntentRulesTests`).

**Settings:** the `intent-forecast` switch (In fights).

## Intent Details

**What you see** (decision #98), during your turn, on each enemy's intent on screen:
- **Block:** on a defend intent, the block its move gains, as a blue number where an attack shows its damage (bottom right of the icon). It's the move's amount through the game's block math as things stand (`Hook.ModifyBlock`: Frail on it, Dexterity), summed when the move gains block more than once. Block it gives another creature (Guardbot's) isn't counted; no number when an amount isn't one the move's code keeps.
- **Buffs and debuffs:** small (a 15 px icon, half a power icon's usual size) in the bottom-right corner of the intent it belongs to (a buff on its buff intent, a debuff on its debuff intent, else its last intent; where an attack shows its damage: `Features/IntentCorner`, decision #99), each power its move applies, with the game's icon and the amount (Strength 3, Weak 2), read from the move's code as Intent Forecast reads later moves (`Sim/Adapter/MovePowers`). A power the move applies on only some of its branches (an if, a switch or a loop decides it: `Sim/Adapter/Branches`, decision #109) shows only when the branch that will run is known: each such move has a rule that picks its branch from what you can see (`Sim/Adapter/MoveBranches`: Entomancer's Pheromone Spit by its Personal Hive, Ceremonial Beast's Plow while it has Plow, Magi Knight's Dampen if you don't have it yet, Ovicopter's eggs while a slot is free, Queen's Strength to her allies (2 at the Dread ascension), Test Subject's Respawn by how many times it has respawned; Spectral Knight's Hex, The Insatiable's Sandpit and Thieving Hopper's Swipe always). Without a rule, and on Intent Forecast's later moves (the state that decides them can still change), such a power shows its icon with a ? instead of a number, and the check doesn't hold the move to it. The icon alone when the amount isn't a number the move keeps.
- **Status cards:** the game already prints the count on a status intent (`StatusIntent`: "3"). Card debuffs (afflictions, a stolen card) get nothing.
- Nothing while the intent on screen is hidden (`HiddenIntent`, `UnknownIntent`).
- **Game UI touched:** our own nodes added under each `NIntent`'s `%IntentHolder` (so they bob with the icon): a label over its `%Value` label, and the power chips in the same corner of the intent they belong to. The game's nodes are never changed.

**Checked** (the end-of-turn check, `ForecastAudit.IntentIssues`): for each enemy that made the move its intent showed, the block it gained during that move and the powers it applied (`PowerReceivedEntry.Applier`) against what was shown: `intent block` and `intent power` issues. A power Artifact took isn't reported; a power shown with a ? (decision #109) isn't held to anything. The catalog tests scan every monster's moves in the installed game (`MoveBranchTests`): a move applying a power on only some branches fails them until it has a rule or a reviewed reason, and a rule whose move changed fails them too.

**Settings:** the `intent-details` switch (In fights).

## Run Reminders

Like StS1's Relic Reminders: outside fights, your relics that change what a choice does are shown on that choice. Every relic and how the mod covers it, in and out of fights: [RELICS.md](RELICS.md).

**Card rewards** (decision #82): on each card a card reward offers, a plain tab (like the other offered-card tabs) for each of your relics that taking that card sets off. Keys `reminder-reward:<Relic>`.
- **Bing Bong:** on every card: the card you take is copied.
- **Lucky Fysh:** on every card: taking one gives gold. None with Ectoplasm, which leaves you no gold to get (the game's own gold query, `Hook.ModifyGoldGained`).
- **Book of Five Rings:** on every card (each counts toward its heal). On the pick that heals, the reach of its count (one card earlier with Bing Bong, whose copy counts too), the game's top-bar heart sits in the tab's corner where the aim marker goes; **crossed** when part of that heal is wasted: it heals more than the HP you're missing (decision #83).
- Pael's Wing isn't shown: sacrificing is the game's own button on the screen, and the relic's counter shows the sacrifices toward its next relic.
- Relics that change the offered cards (eggs, Fresnel Lens, Glitter, Wing Charm, Silken Tress, Lava Lamp, Silver Crucible, Lasting Candy, Prismatic Gem, Dingy Rug) aren't listed: the offered cards already show it.

**Events:** beside each event option (to its left), the icons of your relics that change what it does; crossed (red slash) when the relic works against you. What an option does is read from the option's own code, the game commands it runs (`EventOption`'s OnChosen, following the event's own methods and the delegates the event holds when the option calls one (the Endless Conveyor's current dish), the event's own parts it creates (`MegaCrit.Sts2.Core.Events.Custom`: the Crystal Sphere's minigame and the items it hides, so its card rewards, curse, gold and potions count) and a game mode's reward code (Blitz's Neow pick, `BlitzRunModel.GiveNeowRewards`) but not the options it opens next; a card it makes that is a curse (`ModelDb.Card` of a curse, the curse pool: Wuppy's Injury, the Museum of Torture's pick) counts as adding a curse, whatever command adds it; for an ancient's relic option, also that relic's `AfterObtained`). That's the option's rule, never a roll.

**Which cards an option can give** (docs/CARD_ODDS.md, decision #58): read from the same code, through the game calls that make cards: a reward's `CardCreationOptions` (its pools: a character's, yours or the one the code names, such as Sea Glass's, or `ModelDb.CardPool<T>`, or the pool the option passes in as Colorful Philosophers does; and its filter, the lambda run on each card of the pool, as `GetPossibleCards` and `FilterForRun` do, or every card when the lambda holds a value set while the option runs, such as Glass Eye's rarity), fixed cards (`ModelDb.Card<T>`, `CreateCard<T>`, `CardCmd.TransformTo<T>`), a random transform (`CardCmd.TransformToRandom`, `CardFactory.CreateRandomCardForTransform` as Pandora's Box does: `CardFactory.GetDefaultTransformationOptions` of each card in your deck) and pools used directly (the Museum's curses). The eggs and Fresnel Lens show only when one of those cards is one they change, by their own test (`Data/CardAffinity.cs`: the egg's card type, upgradable and not upgraded; Fresnel Lens `Nimble.CanEnchant`, a card that gains block). An option whose cards can't be read keeps the icon. A curse, a Power-only reward with Molten Egg and the like show nothing.

The same goes for the relics that make certain cards stronger in fights in a way the card doesn't show (decision #59): Strike Dummy and Fake Strike Dummy (Strikes), Vitruvian Minion (Minion cards), Miniature Cannon (upgraded Attacks), Mystic Lighter (enchanted Attacks). Each counts the cards a card makes when played, read from its code (Begone! makes a Minion Strike, a Strike and a Minion), and the change your other relics make to the card you get (an egg's upgraded Attack for Miniature Cannon, Fresnel Lens' Nimble on an Attack for Mystic Lighter). Miniature Cannon also shows on options that upgrade a card of yours when an Attack of yours can be upgraded, Mystic Lighter on options that enchant one when an Attack of yours can take one of the enchantments the option names (`EnchantmentModel.CanEnchant`; Tezcatara's Nutritious Soup enchants your Strikes with Tezcatara's Ember), without a chance: you choose or it's sure. An option that upgrades the cards it gives (Astrolabe) counts them as upgraded: the eggs don't show, Miniature Cannon does. Cannon and Lighter add to an Attack's damage only (`IsPoweredAttack`), read as the card being an Attack.

**The chance** (docs/CARD_ODDS.md, `Sim/CardOdds`, tested), as a small number along the bottom of the icon: that at least one card you're offered is one the relic applies to. Read from the option's code and built by the game's: each reward's options are made by the same factory or constructor with its flags and passed through `Hook.ModifyCardRewardCreationOptions` (Dingy Rug's colorless cards, Prismatic Gem's other characters' cards), and a filter set per pass of a loop (Glass Eye's 2 commons, 2 uncommons and a rare) is read once per value; its rarity odds (`ForNonCombatWithDefaultOdds`: the regular encounter base odds from `CardRarityOdds.GetBaseOdds`, no rarity offset since events roll with base odds; `ForNonCombatWithUniformOdds`: every card equally likely) and how many cards it offers (a constant, or the event's or relic's own `DynamicVars`, as Colorful Philosophers' `Cards` and Sea Glass's `Cards / 3`). Each slot rolls a rarity (a rarity with no card left goes to the next one up), the card is uniform within it, and no card is offered twice; several rewards on one option combine. A random transform shows the chance the new card is one: one value, the same for every ordinary card (a card can't become itself, so it's taken from the card with the most results), and a range only when your deck has cards that transform from another pool (colorless for event, ancient and token cards; every rarity for a curse). None at 100% (a fixed card it applies to), and none when it can't be told: a count or odds the code doesn't show, a pool used directly, rewards mixed with transforms. Not counted: the upgrade roll of Colorful Philosophers' rewards (the other events turn it off). It's the rule's chance, never the roll. The number can be turned off: **Chance under event icons** (General page, on by default). What the icons are for (decision #60): a reminder that a relic makes this choice unusually good or bad; the planned Inspect dialog is for the odds of an outcome you'd like.

## Rest Preview

**What you see:** at a rest site, a sum beside your character (a movable widget, attached on your character's outer side at the fire: left of it when it sits left of the screen's middle, right of it when it sits right (in multiplayer the players sit on both sides; decision #100), the other side when there's no room; a teammate's panel the same way; drag it when the layout is unlocked), drawn like [Incoming Damage](#incoming-damage)'s:
- the top bar's heart and your HP now;
- the Rest option's icon and what resting heals (30% of max HP, rounded down, capped at your max);
- a line per relic or modifier that changes it, with its icon: Regal Pillow (+15, its own line), Stone Humidifier (+5 max HP, which also heals 5), Night Terrors (heals to full, then −5 max HP: a red line);
- at the last rest site before the boss (the boss's map point is next), a line for Pantograph (heals 25) and an unused Bath Robes (heals to full): the result is then the HP the boss fight starts with;
- under the rule, `= HP/max` after all of it, and in orange how much of the rest heal is wasted (past your max HP, or healed anyway by Pantograph or Bath Robes).

Shown while Rest is on offer and not yet chosen (the game's own list of your remaining options), or before the boss with one of those relics (then without the rest lines). Once you click Rest the rest lines go away at once, even while the heal plays out.

**Mend (multiplayer):** while Mend is on offer, hovering a teammate's character shows the same sum for them beside their character (widget "Mend Preview"): Mend heals them exactly as their own Rest would, with their relics (Regal Pillow, Stone Humidifier, Pantograph, Bath Robes), the run's Night Terrors, and the option's own Mend icon. Their relics are on screen for everyone, so it uses nothing a player couldn't know.

**Rules** (decompile v0.113.1, `Sim/RestMath`, tested): the heal is the game's own (`HealRestSiteOption.GetHealAmount`, `MendRestSiteOption.GetHealAmount` for the target: 30% of max HP through `ModifyRestSiteHealAmount`: Regal Pillow +15, Night Terrors to full), and HP becomes the whole part of HP + heal, capped at max. After it (`AfterRestSiteHeal`, on the healed player), Stone Humidifier adds 5 max HP (and HP), Night Terrors takes 5 max HP. At the boss fight's start (`BeforeCombatStart`), Pantograph heals 25 and Bath Robes heals to full, once.

**Check:** after you rest, your HP and max HP against the preview (`[audit] [rest]`, reported as `rest-heal`); after your Mend, the teammate's (`rest-mend`); at the boss fight's start, your HP against the preview for how you left the last rest site (`rest-boss`).

**Settings:** the `rest-preview` switch (Outside fights page).

**Game UI touched:** nothing of the game's: the panels are our own widgets (ids `rest-hp`, `rest-mend`); read: `NRestSiteRoom.Instance`, its characters (`characterAnims`, `GetCharacterForPlayer`, each `NRestSiteCharacter.Hitbox`'s place and whether the mouse is over it), `RunManager.Instance.RestSiteSynchronizer.GetLocalOptions()` (Rest and Mend on offer). **Patches:** `HealRestSiteOption.OnSelect` (observe-only prefix: the check records the preview you chose from, and Rest stops being offered), `MendRestSiteOption.OnSelect` (observe-only prefix and postfix: the Mend check, and Mend is offered again if you cancel the targeting).

## Update Notice

**What you see:** on the main menu, when newer Spire QoL versions are out, a small green note just above the game's "MODDED (n)" text in the bottom-right corner: "Spire QoL: 3 versions behind (new version on GitHub)". Clicking it opens the newest Spire QoL release on GitHub (its notes and download); when you're up to date, Spire QoL's releases, searched by its tag so the repo's other mods' releases are left out. When GitHub confirms you're on the newest version, a muted grey "Spire QoL up to date!" instead. Nothing when GitHub can't be reached, and nothing during a run.

**Checking:** while GitHub hasn't answered yet (the first visit to the menu), the note reads "Checking for Spire QoL updates…" in a faint grey, so it doesn't seem missing.

**Settings gear:** to the right of the note, the game's own top-bar settings gear (`images/packed/common_ui/top_bar/top_bar_settings.png`); clicking it opens the Spire QoL settings menu. It shows on the main menu even while GitHub hasn't answered or can't be reached (alone, where the note would be), and goes with the `update-notice` switch.

**Test builds:** a build whose version isn't one of the releases, or that was built with uncommitted changes, shows two orange lines there instead: its version, the commit it was built from (stamped by the SDK), whether it has uncommitted changes (`GitDirty`, stamped by `Directory.Build.targets` from `git status`) and when it was built; then whether its version number is already released, the newest release, and how many are newer. Release builds are made from a clean commit, so players never see this.

**How it checks:** each time the main menu appears, one request on a worker thread to GitHub's public releases list for this repo (every page, 100 releases each), counting `spireqol-v<version>` releases (not drafts or prereleases) newer than the running DLL's version. It sends nothing about you; the User-Agent is the mod's id. If GitHub can't be reached, the note keeps its last answer (or stays hidden: it never says you're up to date without checking). Turn it off with the `update-notice` switch (settings menu, General).

**Game UI touched:** adds a label and the gear as children of the main menu's `%ModdedWarning` label (`NDebugInfoLabelManager`); the game's own label isn't changed. No Harmony patches.

## Main Saves (separate mod)

**What it does:** while any mod is loaded, the game keeps its saves in a separate `modded` folder (`%APPDATA%\SlayTheSpire2\steam\<id>\modded\`: `profile.save` and every profile's progress, current run, prefs and run history), copied from the normal saves only the first time you play modded. Main Saves makes the game use the normal folder instead, so modded and unmodded play share one set of profiles. The game still knows it's running modded (run history and its own crash reporting behave as with any mod). No settings. Remove the mod to go back to the modded profiles, which are left as they were.

**Harmony patch:** `UserDataPathProvider.GetAccountDir` (prefix): returns the normal folder (`""`) when the game asks for the current mode; calls that name a mode (`forceModState`, the game's first-time copy into `modded`) get the game's own answer. Unlike Spire QoL's, this patch changes what the game does (decision #33).
