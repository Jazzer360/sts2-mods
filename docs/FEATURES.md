# Spire QoL: feature reference

This is the complete list of every change Spire QoL makes to the game. If a change isn't here, the mod doesn't make it. Each feature lists what you see, its settings, which game UI it touches, and the game methods it patches.

**Status key:** 🟢 shipped · 🟡 built, being tested in game · ⚪ planned

Spire QoL is **display-only**. It never changes game state, damage, cards or saves. Its manifest sets `"affects_gameplay": false`, so you can join multiplayer lobbies whose players don't have it. See [MODDING_NOTES.md](MODDING_NOTES.md).

**Only knowable information.** Spire QoL shows only what a player with perfect memory and full knowledge of the game's rules could work out. It never reads the RNG or the seed, the draw pile's order, or an enemy's move beyond the intent on screen. Random effects show their amount, never their target or roll, and predictions that would depend on a roll leave it out.

**Harmony patches: observe-only.** Every feature works by reading live game state once per frame and drawing its own nodes. Nothing in the game's code is replaced or changed. Six patches only record a call: `CardPileCmd.Shuffle` (the play audit counts shuffles, and the predictions forget the known top of your draw pile; the game keeps no record of them), `CardPileCmd.Add(cards, pile, position, ...)` (the predictions remember cards placed on top of your draw pile, decision #91), `EventOption.Chosen` (Event Reminders checks which relics react to the option you chose; a postfix keeps the option's task to know when it ends) `HealRestSiteOption.OnSelect` (Rest Preview checks your HP after resting) and `MendRestSiteOption.OnSelect` (a postfix too: Rest Preview checks a teammate's HP after your Mend). The coverage audit reads the game's compiled code (reflection, `PatchProcessor.GetOriginalInstructions`), which changes nothing.

**Names and ids (decision #185):** each feature's id is what its saved switch, the saved place of its moved widgets and its error reports are kept under, so it stays when the name you read changes: Keyword Tags is `card-indicators`, Proc Tags `proc-indicators`, Shuffle Tag `shuffle-warning`, Potion Tags `potion-tabs`, Prediction Progress `exploration-progress`, the Play audit `proc-audit`, the Coverage audit `coverage-watch`. A feature split out of another (Ethereal Fade out of Keyword Tags; Reward Tags, Event Reminders, Shop Reminders and Map Reminders out of the old Run Reminders, `run-reminders`) starts, on the first load without a switch of its own, as the one it came out of was.

## What the mod adds to the game, technically

- **One CanvasLayer** (`SpireQoL_Overlay`, layer 10) under the scene tree root, holding a toast message and a `SpireQoL_Widgets` container for the floating widgets. **During live combat with no screen open, that container is moved inside the game's `NCombatUi`, directly before the `%Hand` node, so your cards draw over the widgets.** It moves back to our layer when combat ends, when any screen opens over combat, and while the layout is unlocked (so the hand can't swallow drag clicks). It also steps out the moment `NCombatUi` leaves the scene tree (its `tree_exited` signal, before the game frees it: a co-op game over can free it with combat still running) and never moves into a node queued for deletion (decision #102). Widgets attached to a game element read that element's screen position each frame; they never modify it.
- **Floating widgets hide while a game screen covers combat:** the pause menu, draw/discard/exhaust pile and deck views (`NCapstoneContainer.InUse`), card rewards and card-choice screens (`NOverlayStack.ScreenCount > 0`), and the map (`NMapScreen.IsOpen`). Card decorations live on the card nodes in your hand, so they already sit underneath those screens.
- **A second CanvasLayer** (`SpireQoL_Settings`, layer 100) for the settings menu, hidden until opened. While the menu is open it registers itself with the game's `NHotkeyManager` as a blocking screen (`AddBlockingScreen` / `RemoveBlockingScreen`, the game's own mechanism for popups), so game hotkeys do nothing, and pushes its own Esc / back binding (`ui_cancel`, `mega_pause_and_back`, `mega_back`) to close it; both are removed when it closes.
- **Two "Spire QoL settings" buttons** (plain Godot `Button`s) added as children of game nodes while those screens are open: the Mods screen's info panel (`NModdingScreen` → `%ModInfoContainer`, only while Spire QoL is the selected mod) and the pause menu (`NPauseMenu`, bottom-left). Found each frame from `NGame.Instance.MainMenu.SubmenuStack.Peek()` and `NCapstoneContainer.Instance.CurrentCapstoneScreen`.
- **One `SceneTree.ProcessFrame` callback.** It runs each feature, then draws card decorations.
- **A child node `SpireQoL_CardOverlay`** under `%CardContainer` of each card node in your hand that has something to show. While an Ethereal card is shown faded (decision #113), a copy of it (the game's card scene `res://scenes/cards/card.tscn`, the same model, drawn by the game's own `NCard.UpdateVisuals` with the card's pile and preview target) is drawn at full opacity into a `SubViewport` of ours (`SpireQoL_FlatFadeView`), and that image (`SpireQoL_FlatFade`, a `TextureRect` in the container, over the glow and the tags' layer) is drawn at the Ethereal opacity, while the container's own layers have their `Modulate` alpha set to 0 (the card stays in place, so hovering and playing it are the game's own; the glow and the tags stay drawn). The glow (`NCardHighlight`) gets a copy of its own shader material with the card image as a mask, so it isn't drawn where the card covers it and doesn't show through the see-through frame (decision #127); its animated values are copied from the game's material each frame, and its own material goes back when the card stops fading. The copy is drawn again only when what the card shows changes. A card that can't be copied has the container's `Modulate` alpha lowered instead (each layer faded on its own). Everything is restored as soon as the node stops showing that card. The game reuses card nodes, so this matters.
- **A subscription to `CombatManager.CombatSetUp`,** to know the current combat.
- **One file**, `mods/SpireQoL/SpireQoL.settings.cfg` (JSON). Never written to game saves. New on-card tag kinds are added to it as they first appear (saved at most every 3 seconds).
- **Three checks write to the game log** (`godot.log`, lines start with `[SpireQoL] [audit]` or `[SpireQoL] [coverage]`) when something doesn't match what the mod expects, to surface bugs and gaps:
  - **Forecast audit:** (a forecast still on its way when your turn ends, past the audit's 8 ms wait, is kept searching and built when the turn is checked; one that never had a result, or whose search stopped at a cap, is counted as not checked: decisions #104, #107) the Incoming Damage forecast from the last moment of your turn (before any end-of-turn effect: in multiplayer the game waits for every player between its two end-of-turn phases, and your turn is over from the first, `PlayerTurnPhase.End`), against the HP you and Osty actually lost by your next turn (from the game's combat history). A mismatch logs the forecast breakdown and every damage and block entry. The forecast is the simulator's worst branch, not capped by your HP: a hit that kills you (Fairy in a Bottle brings you back) counts its overkill too. HP lost (yours or Osty's) anywhere between the best and worst branch isn't a mismatch, since a random target decides which happens. When every number is inside its range, they must also come from **one** branch (one set of random targets explains HP lost, Osty's, and every enemy's HP, hits through block and death together); otherwise it's reported as "no single branch". Your end-of-turn auto-plays are checked too (the branch must have auto-played as many cards); a turn where one came up that the simulator couldn't play (a pick that changes your hand) or where the count matches no branch isn't checked.
  - **Outcome audit** (part of the forecast audit): the outcome simulator's prediction from that same moment, enemy by enemy, against the history: dead before it acted (predicted in every branch but it acted, or in no branch but it died first; one your Thorns kills during its own attack acted, since its hit still lands; this is what checks the lethal tag), its HP when your end of turn was over and the damage instances that got through its block then (what Slumber and Asleep count), counted up to the hit that killed it (an enemy its own death brings back, the Waterfall Giant with Steam Eruption, is counted from its return, as the simulator follows it: decision #276), against the branches' range, and for Imbalanced enemies whether it set off its stun (its code's test: any hit of its that a block took whole, any player's) when every branch agreed (decision #273). Only what no branch allows is reported, so a random target never causes a report; if the simulation was truncated, only the guarantees it still makes are checked. Reports carry the simulator's per-enemy prediction, its exact start state as JSON (to replay offline: `tests/SpireQoL.Sim.Tests/Cases`), and the full numbered history window, enemy turn included. Every enemy turn also writes one `[audit] [outcome]` line to the log, predicted vs actual for each enemy, matched or not.
  - **Forecast audit** also checks the end-of-turn block it predicted, and splits the history by whose turn each entry happened on, so Poison ticking at the start of your next turn isn't counted.
  - **Play audit:** the tags a card had on its last frame in your hand (every tag the mod predicted, including ones hidden in settings) (a play can start several frames after the card leaves your hand, while the game's action queue is busy), against what the play did. A card play is one action in the game's action queue (`PlayCardAction`): spending its cost, "before play" procs, the card, "after play" procs, exhausting or discarding it, and every draw or effect its hooks set off. Everything that happens while that action is running belongs to the play: history entries (`CombatHistory.Changed`), relic and power flashes, and shuffles (`ActionExecutor.BeforeActionExecuted`, and again when it resumes after a choice such as Burning Pact's pick). Potions and ending your turn are other actions, so they never mix in. The play is checked when its action finishes (`GameAction.AfterFinished`), against a prediction rebuilt the moment its action starts, from the board at that moment, through the same code as the card's tags (decision #28): nothing is pending ahead of it, so plays made while another was resolving are checked like any other. A prediction whose simulation is still running past its wait as the play begins goes on in the background, from the start state it was given, and the play is checked once it's done, as any other (decision #298: waited for, two seconds at most, as the fight's log goes; still running after 600 frames, its simulator checks are counted as not checked). Play Preview of a play that wins the fight is held to it: no damage after it, and every enemy it killed dead in some outcome. When the fight is ending as the play finishes, the state after it isn't compared (the fight's cleanup changes it); the history checks still run, but less proc damage or block than predicted isn't reported then (the game stops logging history from the hit that ends the fight, `CreatureCmd.Damage`), only more. Cards auto-played by it, such as Catastrophe's, are part of its action. **Tags shown (decision #103):** the proc tags the card showed on its last frame in your hand are held to that same prediction, when nothing came between them (no combat history entry since that frame but the play's own start) and both simulations finished: from the same board through the same code, they must be the same tags, crossed or plain, aim marker, number. A difference is reported as `tabs shown` (a tag drawn from an old frame or a cache keyed on too little, which checking the outcome alone can't see). Skipped otherwise, and counted in the combat summary with the reason (the board changed since they were drawn, a simulation not finished in time or stopped at a cap, tags held from an older result). When that prediction can't be rebuilt, the play is checked against the tags it last showed in hand; if another play or a potion finished after those were computed, its mismatches are logged as `[model]` lines, not reported. Simulator tags (lethal, Imbalanced, wake) of a card whose simulation had no result yet when the audit stopped waiting (8 ms, its own wait: decision #104) aren't reported either. Block from Frost orbs the card evokes counts as its own, and the damage its evokes deal as unsourced damage, both its simulation's (with none finished at the target played at, a card that channels or evokes orbs isn't held to its block and damage, counted). Damage caps flash when they cap a hit (a power whose code caps a damage or the HP it takes and flashes as it does: Hard to Kill, Hardened Shell, Intangible, Buffer); they aren't procs, so they're not reported as missing tags. Neither is Show Off, whose flash on a kill only raises the Show Off card's Aim for a later play. Powers enemies apply to each other (Heist) aren't the play's doing, nor are powers a kill gives back by no one (Possess Strength returning the Strength it took). **Random outcomes aren't reported:** when a play's result depends on a roll with more than one possible target (a random-target proc such as Juggernaut, Kusarigama, Tingsha, Forgotten Soul; a Lightning evoke; a random-target attack; all with several enemies alive), only effects the combat history shows a random hit caused are logged as a `[model]` line instead of a mismatch: an enemy power firing after that enemy took random damage (no card source, or this card's random-target hit) or after a random kill; Gremlin Horn, extra summons, draws, cards or powers after a random kill. Everything else in that play, and every play without randomness, is still checked, so multi-enemy fights still verify their tags. Reports are grouped by cause: which powers for "unexplained powers", and more or less than predicted for amounts. It logs: a relic or power that fired with no tag; a relic tag whose relic didn't fire; proc block that differs (exact; block from any card's own play, including the next one and auto-played ones, isn't proc block); proc damage outside the tags' predicted range (to enemies and to you); and a **budget** check: draws, exhausts, discards, created cards, orbs, summons (a card that summons every player, Legion of Bone, up to its own on each; the Die For You a new Osty gets from the summon is expected) and powers applied beyond what the card itself does (its simulation's counts, the most over its outcomes at the target it was played at: every play of a replay and what they set off; with no finished simulation there the budget isn't checked, counted with its reason) plus what its tags can add are logged as "unexplained" (a missing tag). What a tag's source can add is read from its code (`ProcAudit.EffectsOf`): one the simulator models adds only the powers it applies and the summons it makes (its draws, made cards and orbs are already the simulation's), one it doesn't model whatever its code does, one that plays cards whatever they do. A power that went down with no tag is expected where its own outcome rule says ending the turn now already sets it off (`CardTabs.AlreadySetOff`: a stun, a wake). Fewer draws or orbs channeled than predicted is reported too, since neither is a choice: except when the fight ended, when fewer cards were exhausted than the most it could (draws per exhaust), or when you have no orb slots left. Fewer exhausts, discards or created cards than predicted are only logged (those are often "up to" counts you choose). The game logs a transformed card (Begone, Charge, Guards, Seance, Compact, Primal Force) as created, so up to what the card can transform counts as its own created cards there; nothing else treats a transform as a created card (the game's created-card hook doesn't fire for it). A card's own powers are its power values plus every power its own code applies (`PowerCmd.Apply<T>` calls, read from the compiled card class). Windows with auto-played cards skip the budget: those cards are random, so nothing predicts them. Less than the card's own is a `[model]` line (our model of the card is off, or a pile ran out). Draws are checked against all the draws the play sets off (Dark Embrace and the rest, see [Shuffle Tag](#shuffle-tag)), so their tags no longer excuse extra draws; powers that react to which card is drawn (Pagestorm, Iteration, Hellraiser, Chains of Binding) firing on a play that drew are noted, not reported. **Shuffle:** whether the play shuffled your discard pile into your draw pile (an observe-only prefix on `CardPileCmd.Shuffle`: the game writes no history entry for it) against the prediction behind the Shuffle Tag; a predicted shuffle that didn't come because the play ended the fight is only logged. **State after the play:** when the play's action finishes (it has fully resolved, nothing else has run), the simulator's state is rebuilt from the game and compared with the simulator's own prediction of that play (the same start state and play behind the card's lethal, Imbalanced and wake tags): each enemy's HP, block, poison, Flutter and intent (its hits as they would land on you in the predicted state, so what the play changed counts: Weak, Tainted, Conductor's Baton), your block, Plating, Juggernaut, Thorns, Flame Barrier, Feel No Pain, orbs (an orb another mod adds matches anything), Osty (not after a summon), and in multiplayer each living teammate's block and HP (Beacon of Hope's share). Random targets are branches; only a state no branch gives is reported, one issue per difference from the closest branch, with both states as JSON. Not checked with auto-played cards. A card aimed at a teammate (`AnyAlly`, such as Ignition: the Plasma goes to their orbs) isn't checked against its prediction while the simulator applies it to you: the play's differences are logged, and the coverage audit lists the card. **Every power:** every power on every creature is snapshotted when the play's action starts and when it finishes; a power that went down or away with nothing in the play to explain it is reported (grouped by power). Explained: powers the card (or a card it auto-played) applies, powers that flashed (they acted), sources with a tag, Artifact when the card applies debuffs, temporary powers, the simulator's own powers (compared above), and anything on a creature that died. **Another action inside your play (decision #29):** while your play waits for your choice, the game can run a teammate's queued action; its history entries and flashes are kept out of your play, and for that play the snapshot checks (state after the play, every power, everything else) are logged with the action that ran instead of reported, and counted in the combat summary. **Everything else:** energy, stars, gold, every creature's HP and max HP, every card of yours (pile, cost, upgrade, keywords, affliction, enchantment) and every relic's counter and status, before and after the play. The played card's cost going back up is the game clearing its "this turn or until played" cost (Splash, Bullet Time), not a change to explain. A change must be explained by code that ran: the card's own class, a source with a tag, a source that flashed, a card it auto-played or drew (and its enchantment), or a source that reacts to draws when it drew; each is checked by whether its compiled code issues the game command that makes that change (`CodeIndex`). Anything else is reported as "untracked" with the sources present whose code could have done it, grouped by those sources. A relic whose counter or status changes with no tag, tracker row or flash is reported too (goal 2). **Crossed relic tags (decision #117):** a tag for giving up a relic's bonus is held to what the game shows, both ways: Art of War, Ripple Basin and Pael's Eye going dark (their Active status cleared by the play), Pael's Tears by the energy the play spent and what's left once it's over, Pocketwatch by its count of cards this turn going past its limit. Your energy after the play (and each teammate's) is compared with the prediction in the state after the play. A power or relic worked out from its own code is held to a flash where its code calls `Flash()` (decision #199), not wherever it acts: one that acts without flashing isn't expected to flash, and one that only flashes is. A flash its code calls on a test Spire QoL doesn't read isn't held either way (skipped and counted with why: decision #202), and the rest of its code is still worked out.
  - **Coverage audit** (`coverage-watch`): every game class (relic, power, card, monster, orb, potion, enchantment, affliction) that overrides a combat hook (`Diagnostics/CoverageHooks.txt`: events and rules during a fight that the game's own damage, block and play-count math doesn't already cover) has an entry in `Diagnostics/CoverageLedger.cs`, written from its hook bodies in the decompile: covered (and by what), ignored (and why it can't change a prediction), or a known gap. When the mod loads, the running game's classes are compared with that ledger by reflection, on a worker thread: a class that's new, whose hooks changed, or that has no entry is unexpected, and the first time it shows up in a fight (a relic you have, a power on anyone, a card in your hand, an enemy, an orb, an enchantment or affliction on a card) it's logged and reported once. Known gaps are logged when present, not reported. Card code is checked too: every card's play code (read from the compiled game) is compared with what the mod counts for it, through the same functions the predictions use (draws, orb channels, block, poison, Weak, exhausts, discards, created cards, Sovereign Blades from forging, transformed cards, stars, an attack's hit count when its code sets none and it has a Repeat value), on the card and on an upgraded copy (a card that only does it when upgraded counts), and a card whose code does something uncounted is reported when it shows up. The settings are checked at load: every proc rule (read from the compiled rule code), tracker row and double-play source in the game has a settings row, every row still has something behind it, and every feature has an on/off switch; a tag kind shown in play that the settings don't describe is reported as it appears. A summary line at load gives the counts, and a warning when the game's version isn't the one the ledger was made from. **Relic tracking** (goal 2): every relic that can affect a fight (any public hook outside `Diagnostics/OutOfCombatHooks.txt`) has a tag, a tracker row, or a reviewed reason in `Diagnostics/RelicTracking.cs` ("none: ..." or "gap: ..."), written from its hook bodies; one with none of these, or one new in a game update with fight hooks, is reported when you have it. Cards aimed at a teammate or at every player (`TargetType.AnyAlly`, `AllAllies`) are listed until the simulator models their effect on teammates (it applies them to you); those are reported only in fights with other players.
  - **Teammates (multiplayer):** the forecast audit also compares each teammate's HP lost over the round, and their Osty's, with their predicted range, on every game (decision #30: Teammate Incoming Damage shows it, and a teammate is simulated through its own path). The check uses the cards in their hand whatever the setting (decision #25); the log line also gives the range shown, when leaving their hand out made it differ. Skipped when a teammate auto-played a card at end of turn (Stampede). When you auto-played cards from your hand (Stampede, Simpleton: a random card at a random target), the check keeps only the branches that picked the same cards at the same targets, as the game's history shows them (decision #86); a mismatch when no branch did. The turn isn't checked only when the pick that happened drew or made cards (what follows it isn't simulated), or for an auto-play from another source; the log says so. A turn followed by an extra turn (The Hanged Man) has no enemy turn to compare and isn't checked. A forecast whose search stopped at a cap (decision #107) showed `?` and promised nothing past what was settled, so its turn isn't checked (counted; the cap itself is reported). A forecast with a branch it didn't model isn't checked. Every turn not checked is counted by reason in the combat summary (`enemy turns not checked: ...`), and so is what the forecast didn't model (`not modelled in the forecast: ...`, each also logged as `[audit] [gaps]`): decision #92, gaps to close, not passes. A turn that ends in your death is checked as soon as you die (the fight ends before your next turn): your death against the forecast's (a mismatch when no branch had you dying), and each enemy's death before acting and HP at your turn end as usual; the HP you lost isn't compared, since the hits after your death never came.
  - **A card with no simulation** (building it failed, reported as a crash on its own): its checks of the simulator's tags are skipped and counted (`no simulation for this card`), not reported again.
  - **Every indicator's states (decision #95):** the lethal tag is held to the end of turn simulated from the board the play left (an enemy dead in every outcome of the card must be certain to die from it; one alive in every outcome must not die). The state after the play includes your hand's size (what it discarded, exhausted, drew and made). A play that ends the fight has no board after it to simulate on, but who it killed is known: an enemy it was predicted to leave alive in every outcome must not have died; one predicted to die that is alive as the fight ends (it fled, or the fight ended with you) isn't checked, and is counted. Every tabbed source the play sets off in every outcome, powers and crossed tags included, must flash when its code flashes in a hook of its own (`didn't fire`; a flash only after changing a hit's damage or block, as Slow's, doesn't count: the damage and block checks cover it). A proc set off by a random hit or a drawn card is excused only when some outcome the simulator explored set it off. Each death chance the end-of-turn forecast shows between 0 and 100% is logged with what happened (`[audit] [odds]`) and totalled per fight and session; a total far outside the chances (more than 4 standard deviations, over 30 or more) sends a report.
  - **Summaries:** at the end of each combat, one line per audit: `card plays checked, N matched (issue counts)`, `enemy turns forecast, N matched`, and `chances: N shown, M happened, expected X–Y`.
  - Both only read the combat history and subscribe to relics' and powers' `Flashed` events. They're the features `forecast-audit` and `proc-audit`, on by default.
- **Error reporting** (setting `ReportErrors`, on): crashes caught anywhere in the mod (feature errors, frame errors, tag layout, card predictions) and every audit mismatch are sent to the mod's own Sentry project. A report is built on the game's thread (it reads the game's state) and handed to Sentry from a background one; a mismatch carries no captured stack; a report that takes 20 ms or more to build logs which stage took it (`[perf] building a ... report took`). A game member the build names that the running game doesn't have (another game version or branch) groups as one report per member, wherever it failed. Every report is tagged with the mod and game versions, and how many players were in the fight and their characters (yours first), so multiplayer reports can be told apart; they get a `multiplayer` label and their own per-session budget (at most 40 each, single-player and multiplayer), so a co-op session can't use up the reports a single-player fight would send. Play audit reports also carry the full window: every history entry from just before to just after it, numbered by position and described in our own words (the game's text for a draw says "discarded"), with relic and power flashes at their positions and markers for the window and the play's start; what the card itself was expected to do (draws, exhausts, orbs, hits, orb evokes, random outcome); tags hidden by settings; every play this turn so far (card, its tags, matched or what didn't), the state just before the play started (player, powers, relics with their counters, orbs, enemies, hand with tags), how many frames passed between the card's last frame in hand and its play starting, and the history entries of the play's action. Each report carries the game state from `Diagnostics/Snapshot.cs`: combat, player, powers, relics, orbs (front first, with passive and evoke values and slot capacity), enemies with intents, the hand with each card's tags and play facts, the last 40 combat history entries, the audit window, and the last 80 mod log lines. It uses the game's own Sentry .NET (`Sentry.dll`) through a separate `SentryClient` with our DSN. `SentrySdk.Init` is never called, so the game's own reporting is untouched and no global handlers are installed. There's no machine name, user or personal data. Each fingerprint is sent once per session, at most 40 events. Mismatch fingerprints leave out amounts, so the same bug groups into one issue. Mismatch reports also carry searchable tags: `card` (the card played), `check` (which check failed), `source` (the relic or power the issue names), `effect`, `encounter` and, for the forecast audit, `monster`. Every report is also tagged `other_mods` with the other mods loaded (id and version). While another loaded mod changes the game (its manifest says `affects_gameplay`, or leaves it out, the game's default; or its code adds game content: any card, relic, power, monster or other model), no mismatch is sent, and a crash is sent only when none of that mod's code is in its stack (a frame in its assemblies, or a game method it patches): our code failing on a modded game still reaches us. A mod listed in `reporting.json`'s `gameplayMods` counts as changing the game whatever its manifest says (decision #97). Reports carry `gameplay_mods` too. The log says once what wasn't sent and why (`core/Game/OtherMods.cs`, decisions #34, #96). Handlers on the game's own events and every patch body catch their exceptions, so nothing of ours throws into the game's code. Nothing is sent from a build older than the oldest version reports are still taken from: at startup the mod reads `reporting.json` from the repo on GitHub (one request, the mod name as the user agent, nothing about the player; `core/Diagnostics/ReportFloor.cs`, decision #81), and until it answers, or if it can't be reached, reports go out as usual. An hourly GitHub Action mirrors new Sentry issues to GitHub issues (`auto-report`).
- **Session summaries** (decision #108; feature `session-summary`, "Session summary" on the General page, on; sent only while `ReportErrors` is on too): at the end of each play session (a run started or continued, until it's left: save and quit, back to the menu after a win, a death or abandoning it, or the game closing) that had a fight turn, one summary of counts goes to the same Sentry project: fights and turns (each turn clean, unchecked, capped or mismatched, from the audits), the checks done and skipped (with the reasons, the most frequent 15), the simulator's searches (how many, in the background, cancelled, caps, time percentiles, the slowest, the most states held), the frame's waits, how long the board took to settle when it didn't in its frame, the mod's time per frame and the game's own stalls, garbage collections, reports sent, the session's length, players, your character, the CPU's core count and whether other mods were loaded. Nothing personal, no game state. It's sent outside the per-session report limits (one per session). The summary so far is kept in `mods/SpireQoL/SpireQoL.session.json`, rewritten at each turn and fight: a session the mod didn't see end (a crash) is sent on the next launch. The log gets the same counts (`[session] ended`). The hourly GitHub Action adds the summaries up per version in a pinned issue (`session-metrics`). Fed by an in-process event stream (`Telemetry/DevEvents`) that the audits, the simulator and the reporter post to, and by the overlay's frame timing (`OverlayHost.FrameMeasured`). The session's bounds are read from `RunManager.IsInProgress` and its private `State`, how it ended from `IsAbandoned`, `IsGameOver` and `HasRunEnded` (beta branch only; read by reflection). No patches.
- **Dev mode** (decision #108; setting `DevMode`, in the menu's General page only in a developer's game): on when a developer's install left `SpireQoL.dev` beside the DLL (release zips never contain it), or when `DevMode` is `true`; `false` turns it off. Reports and session summaries from that game are tagged `dev`, and the session metrics leave them out. Nothing from that game goes to Sentry: each report is saved as `reports/{id}.json` in the dev folder instead (everything the event would have carried), and each session summary as a line of `sessions.jsonl`, whether `ReportErrors` is on or not (`ErrorReporter.Local`). It writes the dev dashboard's files to `%USERPROFILE%\SpireQoL-dev` (or the hidden setting `DevFolder`; `Telemetry/DevSink`, `DevDashboard`): the event stream with each feature's name once a launch (`feature-names`, decision #185: the dashboard shows the names a player reads, a part of a feature as "Rest Preview: read", with the id on hover), frame rollups (each feature's time and memory per frame, from `OverlayHost.FeatureMs` and `FeatureKb`, the mod's code in the game's hooks among them; the searches' memory on their own threads, `SimJob.AllocatedBytes`; the engine's shader compiles and node counts, read once a frame; whether the moment was quiet, steady throughout, and the dev checks in it, whose time and memory are counted as `dev-checks`, not their feature's (`OverlayHost.CountDevWork`); nothing about frames while the game's window is in the background or on its first frame back, `focus-changed` marking the time away (decisions #179, #238); every 10 s what each feature allocated on steady frames, where nothing the mod reads had changed for a second (the board probe, the screen, the control under the mouse, anything held, the settings, searches running), however little, with how often, each one's first sighting in the log as a `[steady]` line (`Telemetry/SteadyWatch`, decision #177)) and the mod's log lines (`ModLog.Written`), a state snapshot (where you are, the session's counts, the turn forecast now, the performance trace recording now), and keeps the reports and session summaries. The page, `tools/dashboard/index.html`, isn't part of the mod (docs/DEVELOPMENT.md "Dev dashboard"). With dev mode off none of this runs.
  - **Record a performance trace** (decision #258; setting `TraceLevel`, on the General page under Dev mode, only in a developer's game): Off, Memory (the default) or Full. While it isn't Off, Microsoft's `dotnet-trace` (an external tool the developer installs; looked for on PATH and in `%USERPROFILE%\.dotnet\tools`) runs as a child process attached to the game's own process, from the mod's load or the moment the setting changes, writing `traces\trace-yyyyMMdd-HHmmss-<level>.nettrace` in the dev folder, a new file each launch and each change of level. Memory: the runtime's garbage collection events at Verbose (each collection's generation, pause and heap sizes; an allocation tick about every 100 KB with its type and stack), with its loader, JIT and exception events; Full adds the runtime's CPU sampler. Off, or the game closing, stops it with the mod's own event source (`SpireQoL-Trace`'s Finish, which dotnet-trace waits for: its stopping event), waiting up to 30 s (10 s at exit) for its file to end before it's killed; on Windows it runs in a job that ends with the game's process. All of it on its own thread (`Telemetry/TraceRecorder`); the frame never waits on it. The traces keep to a disk budget (hidden setting `TraceBudgetMb`, 2048 MB): the oldest past it are deleted, and a recording that alone fills it stops. dotnet-trace missing: nothing runs, the row says so with the command that installs it, and the log says it once. The dev stream marks each recording (`trace-started`, `trace-stopped`) and `state.json` says what's recording. Read afterwards with `scripts/trace-report.ps1` (`tools/TraceReport`, not part of the mod) and the dashboard's Traces page (docs/DEVELOPMENT.md "Performance traces"). No patches.
- **Error logging is capped:** a failure that repeats every frame is logged in full once, then as a count every ~600 repeats.
- **Slow frames:** the mod times its own work each frame (each feature; each job that runs after them, under its own name: `settings-menu`, `card-tabs` with `ethereal-fade` apart, `settings-save`, `dev-dashboard`; widget layout). Every frame where that took over 30 ms logs a `[perf] slow frame` warning with the time per feature. Over 50 ms it's also reported as an error report (`perf`, grouped by the slowest feature, with the usual game state), from that feature's second such frame in a session (the first can be its code warming up); a freeze of a second or more is reported the first time. A frame over 50 ms where the mod's share stayed under 30 ms is mostly the game's (a slower PC, loading, room changes, drawing): logged as an info line with the mod's share in its frame and in the game's hooks (its Harmony patches and its handlers on the game's events, each timed with `OverlayHost.TimeHook` and shown in the frame times as `hook:<id>`), and in dev mode the engine's shader compiles since the frame before; at most one every 2 seconds with a count of the ones in between, and never reported. A new Relic Counters row is timed on its own (`relic-counters:row`: it loads its icon).
- **Observe-only patches.** Prefixes that record the call and change nothing: `CardPileCmd.Shuffle` (play audit; the predictions forget your draw pile's known top), `CardPileCmd.Add(IEnumerable<CardModel>, CardPile, CardPilePosition, AbstractModel, bool, bool)` (the predictions remember cards placed on top of your draw pile: decision #91), `EventOption.Chosen` (Event Reminders check) and `MonsterModel.RollMove` (Intent Forecast audit: works out the forecast before the roll); postfixes that only read: `EventOption.Chosen` (keeps the option's task to know when it ends) and `MonsterModel.RollMove` (compares the rolled move with the forecast); everything else is read from live game state each frame; the game's hook queries it calls (`Hook.ModifyCardPlayCount`, `ModifyBlock`, `ModifyDamage`, `ShouldEtherealTrigger`, `ModifyOrbPassiveTriggerCount`) are pure queries with no side effects.

## On-card tags: one language for everything on a card

**The question every tag answers: does something happen the moment I play this card, right now?** Exceptions: the Retain tag, [Ethereal Fade](#ethereal-fade) (not a tag), and the tags on cards you're offered outside fights (below: "this relic makes this card stronger", decision #62).

Every indicator about a specific card in your hand uses the **same form**: a **tag** hanging up off the card's **top edge**, centered in a row, one tag per effect. In a fanned hand the tops of cards stay visible while their sides are covered, so you can read the tags at a glance without hovering. A tag means something out of the ordinary will happen when you play that card.

- **Look:** each tag is a copy of the card's own enchantment tab (the game's banner art), always at full color (never the grey the game gives a disabled enchantment), rotated a quarter turn so it hangs off the top edge the way an enchantment tab hangs off the side. **It draws beneath the card art but above the card's glow**, tucked about 17% under the top edge, so the card itself covers the tucked part. The icon is drawn slightly smaller (85%) and sits just below the middle of the part of the tag that shows above the card. Tags stay on a card while you hold it to play it (dragging or aiming): the game moves a held card out of the hand's holder container (`NPlayerHand.StartCardPlay`), so the held card is found through the hand's current card play (`NPlayerHand._currentCardPlay`, read only). Each tag carries the icon of whatever is affecting the card: a relic, power or enchantment, or the draw pile.
- **Text instead of an icon only for replay and draw chances:** replay on the card itself has no power or relic to show, so its tag reads `2×` (total plays); a card whose effect depends on what it draws shows that chance (`40%`, decision #119), with the most likely number centred above it for Pillage and Scrape (decision #124). The text fills the icon's slot (the tag's own auto-sizing label gets the icon's box and a larger maximum font size).
- **Numbers only for amounts:** a tag shows a number only when the proc gains you block, deals damage, summons, draws cards or gives energy, or puts cards into your piles, and the amount is the point (e.g. Feel No Pain on True Grit: `3`; Motif at 2 on a card that's your first Wah and Cho this turn: `4`; decision #132; Personal Hive at 2 on a 3-hit attack: `6` Dazed, decision #161). Free-card tags show the energy the free card saves, or `?` when you couldn't know what the card costs, which the free card hides (Snecko Eye, Frantic Escape; decisions #44, #47, #54). It sits at the icon's lower-right corner, like a power amount. Everything else is icon only.
- **Plain vs crossed:** a plain tag means playing this card does something extra. A crossed tag (red slash) is a warning: playing it might be bad for you, because it helps the enemy (Enrage, Curl Up), hurts you (Thorns, Galvanized) or gives up a relic's bonus (Art of War, Pael's Tears, Orichalcum), or makes it smaller (Cloak Clasp, Obsidian Vice: off by default). Which directions of a relic's or power's bonus get a tag is its row's (decision #244).
- **Aim marker:** a tag whose effect happens only at some of the targets you could aim the card at (enemies, or teammates for cards aimed at them) gets the head of the game's targeting arrow over its icon's top-left corner (decision #55), at 60% of the icon's size and reaching past its top and left edges, clear of the slash and the number. Each target is simulated on its own: the tag shows when some target gives it (every random branch for good tags, any branch for warnings), and the marker when not every target does. So a lethal skull, Mighty Wings or a Curl Up warning with the marker means "aim at the right one" (or, for a warning, "aim elsewhere to avoid it"). Several enemies sharing a tag get the marker only when some target sets off none of them. Untargeted and random-target cards never get it.
- **Heal marker:** Regen's green plus (the Regen Potion's buff icon) in the same corner, on a card reward's Book of Five Rings tag when taking that card makes it heal now (decision #83); crossed when part of the heal is wasted.
- **One per source:** each source shows at most one tag per card. Tags keep their size and spacing; if a row would be wider than the card, only the gaps shrink (tags overlap, later ones on top), so a row never spills past the card's edges.
- **Not tags:** the only on-card effect that isn't a tag is **Ethereal Fade**, the see-through Ethereal card (a feature of its own).
- **Not marked: cards that can't be played.** The game already crosses out the cost of a card that can't be played for any reason other than cost (`NCard` unplayable energy/star icon) and drops its glow, so there's no tag for it (removed in 0.23.1).

## Keyword Tags

**What you see:** mid-combat changes to a card in your hand that the game otherwise shows only as text, as on-card tags (see above).

- **Retain:** a Steady tag (Steady is the game's Retain enchantment). **Sly:** a Master Planner tag (the de-facto Sly power). Granted-for-this-turn (Expertise, Hand Trick) looks the same.
- **Replay** on the card itself (Hidden Gem, Transfigure, Sword Sage on Sovereign Blade, enchantments): a text tag `2×`, the card's total plays (`CardModel.GetEnchantedReplayCount` + 1). The card text says "Replay", but it's easy to miss without hovering.
- **Added keywords get no tag:** the game prints every keyword a card currently has (including added Exhaust) on the card itself. (The Goopy "added Exhaust" tag was removed in 0.21.0.)
- **Blocked cards** (Bound, Ringing, Smog, Velvet Choker): no tag since 0.23.1. The game's own crossed-out cost shows it whenever `CardModel.CanPlay` fails for a reason other than cost, which covers every case the old tag did.
- **Galvanized** moved to [Proc Tags](#proc-tags) in 0.19.0 (crossed Galvanic tag with the damage you take).
- **Double play:** one tag per source, with that source's own icon: the power (Echo Form, Burst, Duplication, One-Two Punch, Signal Boost, Tag Team, Ki Verse) or the relic (Throwing Axe). Replay on the card itself is the `2×` tag instead. The game's query reports which models changed the count, so new sources get their own icon automatically.
  - The count comes from the game's own play-count query, the one it runs when you play the card: enchanted replays + 1, then `Hook.ModifyCardPlayCount`. So it covers Echo Form (first N cards each turn), Burst (skills), Duplication, One-Two Punch (attacks), Signal Boost (powers), Throwing Axe (first card each combat), Tag Team, enchantments, and anything added later.
  - Not on a card that can't be played (curses, Unplayable statuses, cards blocked outright), the same check the proc tags use; the `2×` tag neither.
  - Tag Team only doubles attacks aimed at the enemy that has it. Single-target cards are checked against each enemy, and the best case is shown.

**Settings:** the `card-indicators` switch (In fights); the Retain, Sly and Replay switches and the double-play family under it (In fights, On your cards).

**Not yet:** free-this-turn / free-this-combat / temporary-cost duration markers, decorations outside the hand (draw/discard views).

## Relic Counters

## Incoming Damage

**What you see**, during your turn (and while you pick one of a few cards mid-fight: a discovery, a potion's choice): a small stacked sum, read like a math problem. It uses the game's own intent icons: defend, and the attack icon tier that matches the incoming total (the same thresholds enemies use: under 5, 10, 20, 40, and 40+):

```
[eye]   +1 turn  only when ending your turn now gives you another turn first (Pael's Eye, Extra Turn): its icon
[attack]  14     incoming damage
[defend] − 5     your block at end of turn
[osty]   − 4     what Osty absorbs (Necrobinder, only while Osty is out; red if it dies)
──────────
      =   9     what gets through your block (red), or 0 in green
[heart]  + 3    only with HP loss no block stops (Regret, Beckon, Bad Luck): what it takes, on its own line so it never reads as block you're short of
[fairy]  31 HP  only when Fairy in a Bottle or Lizard Tail keeps you alive: its icon, and your HP after the enemy turn
```

Beside the last number (the heart line when there is one): a skull when this might kill you, with the chance when a roll decides it, and ? when some outcome has something not modelled, or while the numbers shown are waiting on a newer result for more than 100 ms (decision #107: on a busy board the last forecast stays on screen until the new one is in, and the ? says so; shorter waits show no mark, so it doesn't blink). When the search for every outcome stops at its memory or work cap (decision #107, rare), a lone ? replaces the numbers: no damage and no skull, nothing promised either way. The skull and the chance come from the whole enemy turn, both lines together. With nothing blockable coming, only the heart line shows. Teammate Incoming Damage shows it the same way.

**Extra turns** (decision #40): when ending your turn now gives you another turn before the enemies act (the game's own `Hook.ShouldTakeExtraTurn`: Pael's Eye with nothing played this turn, Extra Turn), the top row shows the source's icon and `+1 turn`. The sum below is still the enemies' next turn, which comes after that one, and the block you gain at the end of this turn will be gone by then.

**Death and what prevents it:** the simulator tracks your HP. Regen heals you at the end of your turn, before the enemies act, up to your max HP. At 0, Fairy in a Bottle is used first (the game asks `ShouldDie` before `ShouldDieLate`), healing you from 0 to 30% of your max HP; then Lizard Tail (50%, once a run). The rest of the hit that took you to 0 is lost, and later hits still land. With nothing left, you die: the skull. The numbers are the most likely outcome (below; the worst with it off). The skull shows whenever some outcome kills you. When a roll decides it, the chance sits left of the skull (`25%`; the Death chance setting). A search that stops at a cap (too many outcomes to finish, decision #107) shows a lone `?` instead of the numbers and the skull, and a result held while a newer one is worked out carries a `?` after 100 ms (decision #105); so does a forecast with an outcome the simulator doesn't model (decision #92). So does one built from something the game wouldn't give (a member a game update renamed or changed): it's named in the reason and reported once, and every prediction built from it shows its `?` until the mod reads it again. A teammate's revives aren't modelled.

**Placement:** it sits just left of your block indicator, at the left end of your HP bar, and follows your character. If that doesn't fit on screen (your character stands near the left edge), it drops below the HP bar and every row of power icons instead; wrapped rows are measured. Move it with F8, or middle-click to pin it to the screen instead.

**How the numbers are worked out:** by the [outcome simulator](#outcome-simulator): your end of turn, then the enemy turn hit by hit, in turn order. Random targets (Lightning, Juggernaut, Forgotten Soul, Parrying Shield) are explored as branches, and the outcome shown is the **most likely** one (decision #155). With one enemy, or when every branch ends the same (two Lightning orbs and two enemies they each kill), the result is exact.

**The most likely outcome, and every other on hover** (decision #155): when a roll decides how the enemy turn goes for you (a draw at the end of your turn, I Am Invincible somewhere in your draw pile, a random target), the branches that leave you the same (HP lost, dead or not, what saved you) are one outcome, their chances added up. The sum shows the most likely outcome, every line from it, so it still adds up, with its chance before the last number (`72%`); on equal chances the worse for you is shown. The skull and its chance show whenever any outcome kills you, whatever the sum shows. The Fairy in a Bottle (or Lizard Tail) line shows whenever some outcome uses it, with its chance and your HP after it. Hovering the sum lists every outcome: the most likely first, then the others from the kindest to the worst, each as its difference from the most likely (`Lose 11 HP (+2)`, `You die`), its chance, and the sources that change (`Burn +2`, `I Am Invincible block +10`); with no roll it says the outcome is certain. A ? there means some outcome has something not modelled, or the search isn't done. The tooltip is the mod's own panel, shown while the mouse is over the sum (the sum takes no mouse input, so it never gets in a card's way). Chances are logged with what happened (`[audit] [odds]`) and totalled per fight and session, the most likely outcome's with them. Setting: **Incoming Damage: most likely outcome** (`MostLikely`, under Show chances, on by default); off, or with Show chances off, the sum is the worst case as before, and the hover lists the outcomes either way.
- **Osty** (Necrobinder): enemies never target Osty, but its Die For You power takes the part of an enemy attack that gets through *your* block (pets share your block), up to Osty's HP; the overkill comes back to you. Damage that isn't an attack (Burn, Constrict, HP loss) isn't redirected. The Osty row uses Die For You's icon. A summon during the play (Bodyguard, Reanimate, Legion of Bone's for every player...) is worked out as the game's OstyCmd.Summon runs it: Osty alive gains that much max HP and HP, Osty dead comes back at the amount, and a first summon gives you him with Die For You; Spur's heal of him stops at his max HP. Damage to Osty himself (an enemy's Thorns as he attacks) meets your block first (a pet's damage is blocked by its owner's block), then his HP. The hit's results are told as the game tells them (decision #264): on v0.114.0 yours first (Flame Barrier, Reflect), then Osty's (Necro Mastery), on v0.111.1 Osty's first. Osty is a creature with his own powers (decision #265): Die For You is read from its code, a power an enemy's reaction puts on him lands on him (Monarch's Gaze's Strength down), none while he's dead, his own Strength is in the hits he deals, and at his death his powers come off but Die For You, which keeps him in the fight for a summon to bring back. A teammate's Osty is the same for them, his result in their fight's log and told to the hooks.
- **Your end-of-turn self damage** lands first, against your end-of-turn block.
- **Your end-of-turn damage to enemies** lands before they act, so an enemy it kills doesn't attack: Hailstorm (enough Frost orbs), The Bomb (last tick), Screaming Flagon (empty hand), Stone Calendar (its turn), Obsidian Vice (its damage per card in hand, one hit on a random enemy), Charon's Ashes (per Ethereal card exhausting), Inferno (each time you lose HP on your turn: Regret, Burn, Decay or other end-of-turn damage that gets through your block; unpowered, so enemy block takes it) and Glass orb passives (base value + Focus; the base drops by 1 each time it fires, never below 0, so a decayed Glass orb still deals your Focus) hit every enemy; Consuming Shadow's evoked orbs (one per stack, last orb first, after orb passives) hit the lowest-HP enemy (Dark, including this turn's growth) or every enemy (Glass); Lightning orb passives and evokes, Parrying Shield, Forgotten Soul and Juggernaut (once per end-of-turn block gain: Plating, each Frost passive trigger, Orichalcum, Cloak Clasp, Ripple Basin, each Feel No Pain exhaust, Consuming Shadow Frost evokes) hit a random enemy, so they're counted only when there's one enemy (with several, a kill we can't be sure of would hide an attack). Enemy block is still up at that point.
- **HP-loss effects**, in the game's order, on every hit that reaches your HP: Tungsten Rod (−1 each), Beating Remnant (caps HP lost per turn), then Buffer (cancels a hit, one charge each). Intangible is already in the enemy intent numbers.
- **Poison:** an enemy that Poison will kill doesn't attack. Every enemy's poison ticks as the enemies' turn starts, before any of them moves (`PoisonPower.AfterSideTurnStart`), so a poison death's reactions come first: Ravenous stuns the other Corpse Slug, Crab Rage hits harder. Each enemy's poison ticks as its own code does (`PoisonPower.Trigger`, read from the game's code): once, plus once for every living player's Accelerant, at most its stacks, each tick a hit of its own for the stacks left (then a stack less), so per-hit caps apply to each tick: Exoskeleton's **Hard To Kill** (each instance capped, e.g. at 9), **Slippery** (1 HP each). Skulking Colony's **Hardened Shell** caps an enemy's *total* HP loss per turn, its budget whole again as the enemies' turn starts.
- **The enemies' turn start:** the powers that react as a side's turn starts do so as the enemies' turn starts, before any of them moves, as their own code says (`BeforeSideTurnStart`, `AfterSideTurnStart`): one that goes as its owner's turn starts goes from an enemy before it moves, and yours last through the enemy turn (Conductor's Baton). What happens as your next turn starts is past every prediction.
- **Your next turn's start, in the Intent Forecast's later turns** (decision #306): the powers and relics that react as your side's turn starts do so as their own code says (`BeforeSideTurnStart`, then your block cleared, each player's `AfterEnergyReset`, `BeforeHandDraw` and `AfterPlayerTurnStart`, then `AfterSideTurnStart`, then your orbs' turn-start passives), its participants you, your teammates and your pets. Your hand and what you'd draw are left out (a roll). One whose code there isn't followed (listed with why, read from its hooks) makes what comes after it unknown, unless all it does there changes only hands, cards, energy, HP or block, which a projection doesn't follow (read from the commands it calls: decision #308). Card simulations end with the enemy turn and never reach it.
- **Doom doesn't stop attacks.** Doomed enemies die at the end of their own turn, after attacking. Doom's kill is read from its code (decision #310: `DoomPower`'s turn's-end hooks, `KillEachStep`): each creature of the side whose turn ends with Doom at least its HP dies (an enemy as the enemies' turn ends, you as yours), then Book Repair Knife heals 3 for each enemy it took whose death sets off Fatal (not a Minion's). End of Days' play kills each enemy its own Doom takes (`KillEachAction`).
- **The enemies' turn end** (decision #302): after the last enemy's move, the powers and relics that react as a side's turn ends do so for the enemies' side, as their own code says (`BeforeSideTurnEnd`, `AfterSideTurnEnd`): Weak, Vulnerable and Frail tick down (on you and on enemies; a debuff an enemy gave you during that turn keeps its stack, as the game skips its first tick), Flame Barrier, Intercept and Cover go, an enemy's Ritual gives its Strength. Nothing shown reads past the enemy turn yet: it's the state the later turns start from. Doom kills the doomed there (decision #310). What it can't follow there (a power or relic with no model whose code acts there, read from its hooks: Battleworn Dummy's time limit, Chains of Binding: decision #303) makes only that state unknown, never what happens up to the enemy turn's end.
- **Each enemy's move, in its code's order** (decision #195): an enemy's move is read from the game's code (the method its `MoveState` performs), so what it does before a later hit changes that hit: Vulnerable it puts on you raises the hits of the enemies after it (Mawler's Roar; Ovicopter's Tenderizer, after its own attack), Strength it gives its side raises theirs (The Obscura's Wail, Queen's Burn Bright for Me), and block it gives an ally takes your Thorns and Flame Barrier on that ally (Guardbot's Guard on a Fabricator). Its own attack is its intent's hits at their place in the move: a power the move applies after its attack doesn't change that attack. A move behind a hidden intent stays its intent alone.
- **A power landing, as PowerCmd lands it** (decision #234): in multiplayer, a new power on an enemy that the game scales for the players (Plating, Artifact, Slippery, Plow, Curl Up...) is scaled by its own class's code (a move's, the powers a creature joining the fight starts with, a card's); more of one already there isn't; and one taken back to nothing goes (a Strength at exactly 0, any other at 0 or below).
- **Each attack's hooks** run around its hits, as the game's attack does (before: an enemy's Vigor keeps the attack; after: Vigor is spent), so an enemy's Vigor raises its move's first attack only.
- **Retaliation** can kill an attacker partway through a multi-hit. Each later hit is then cancelled, because the game checks for a dead attacker before every hit.
  - Thorns hits before each blow. The blow during which Thorns kills still lands.
  - Flame Barrier hits after each blow.
  - Reflect, after each blow, deals the damage you blocked. Flame Barrier and Reflect hit back in the order they landed on you, as the game tells the powers of a hit.
  - Thorns, Flame Barrier and Reflect are worked out from their own code (decision #241), yours and a teammate's, on every damage to a player the same way: an enemy's Thorns hitting Osty takes the damage math for Osty, not for you.
  - Retaliation is damage like any other (each is `CreatureCmd.Damage` in its power's code): the game's damage math (the enemy's caps, Intangible and Hard to Kill, read from their code), the enemy's block, then its HP-loss effects (Hardened Shell, Slippery, Intangible) and what reacts to the hit. It hits the enemy's block first; enemy block is assumed cleared at its turn start unless it has Barricade.
- **Unblockable HP loss** (Regret, Bad Luck, Beckon: anything the simulator lands as unblockable on you) is its own line under the result (the heart), not part of the incoming or the result: block does nothing to it. It's what you lose to it after the HP-loss effects (Tungsten Rod...), the worst outcome's.

  - Frost orbs evoked by Consuming Shadow (their evoke block)
  - Orichalcum / Fake Orichalcum (only if you have 0 block when your turn starts ending: BeforeSideTurnEndVeryEarly, before Pael's Eye exhausts your hand)

## Proc Tags

**What you see:** on each card in your hand, a tag for every power or relic that playing it would set off right now, with that source's icon (see "On-card tags").

**How it's worked out (1.0.0, decisions #48, #49):** the card's play is simulated once per target by the [outcome simulator](#outcome-simulator). Every power and relic that acts on plays, hits, block, powers landing or card events is a model of its game hook, and it logs what it did. A tag shows when its model fired during the play: in every branch for some aim (plain), or in some branch for any aim (crossed). A power the card itself gives you counts too when it fires on that same play (Pale Blue Dot as your 5th card this turn). Effects that play off each other chain on their own: a draw from Dark Embrace sets off Speedster, The Sealed Throne's stars set off Black Hole, Kunai's Dexterity counts for the block that comes after it.

**When it's worked out (decision #114):** only when something changed: the board as the simulator reads it, the fight or turn, the tag settings, or a card in hand (its numbers, cost, keywords, affliction, plays, or whether it can be played). While nothing has, and every result is in, the last frame's tags stay. Where you aim never matters: a tag that needs aim is worked out for every target.

- **Plain tag:** it triggers (Strength, channels, upgrades, creates cards...).
- **Tag with a number:** it gains you block, deals damage, summons, draws cards or gives energy, or puts cards into your piles (Personal Hive's Dazed: decision #161), and the number is how much. Draws are the cards it really draws (decision #132): one at a time from your draw pile, none past 10 in hand, the discard pile shuffled in when the draw pile runs out; energy is what it gives. Draw tags: Dark Embrace, Vicious, Motif, Game Piece, Iron Club, Joss Paper, Centennial Puzzle. Energy tags: Subroutine, Yah!, Orbit, Automation, Ivory Tile, Nunchaku. Block uses the game's own block math (`Hook.ModifyBlock`), so Dexterity and Frail count where they apply. Block and damage are what the simulated play gained or dealt in total (every enemy hit, each through its own modifiers), the most that some aim guarantees.
- **Crossed tag:** it helps the enemy or hurts you; a number is the damage you take.
- **Multiplied by plays:** a card that plays twice (Echo Form, Burst...) sets off per-play procs twice. Procs that fire once per card (Black Hole, stars spent, exhausting itself) count once. Each replay has the numbers the plays before it gave the card (decision #160, read from its code: Rampage, The Ball, Claw and Maul's Increase; Goopy's +1 block; Momentum's damage by its amount; Vigorous's bonus on the first play only, since it turns itself off); a card whose replay changes some other way (Thrash) is `?`. Each play is the game's own play on the board the one before it left (decision #189): what it takes from your hand, the hits or cards that count what it took, and the room in your hand are worked out as each play runs (a replayed Fiend Fire takes the hand each play finds), and the card goes to its pile once, after the last play. What its code tests is asked on each play too, as it runs (decision #190): Sacrifice replayed finds Osty gone on its second play, Impatience draws again only when its first draws brought no Attack, Sunder's energy follows its own hit's kill.
- **Indirect procs** (setting `ProcIndirect`): cards that exhaust or discard other cards, draw, or create cards count what those set off too, through the whole chain (what a drawn-card proc sets off in turn counts as well). For example, with Feel No Pain, True Grit shows the block from exhausting another card. Choices you make mid-play count as the most the card can do (Purity, Hidden Daggers).
- **The Boot:** a plain tag on an attack with a hit it raises: one that gets past the enemy's block for less than its minimum (6 into 5 block loses 1, raised to 5). With the aim marker when only some targets have that hit; a hit block stops entirely, or one already at the minimum, isn't raised.
- **Counter relics** (Kunai, Shuriken, Ornamental Fan, Nunchaku, Kusarigama, Letter Opener, Tuning Fork, Iron Club) show only on cards that complete the count; the tray shows progress.
- Several enemies with the same power share one tag, amounts added.
- **Teammates' sources** (decision #75): a teammate's powers and relics are sources too, so what your card sets off for them gets a tag like your own (their icon; plain or crossed by the same rule). A source you and a teammate both have shares one tag, amounts added. The simulator logs a teammate's firings under their id (`Name@id`), so theirs never count as yours. The play audit watches every player's relics and powers.
- Cards that can't be played (Unplayable, blocked, or their own condition unmet, via `CardModel.CanPlay`) get no proc tags. Cards you can't afford yet still show them, since energy can come mid-turn.

**Uses or breaks a relic** (formerly Relic Reminders): Pen Nib ready (attacks: read from its code, decision #272, the 10th Attack's card play is the doubled one, its owner's hits and their Osty's, a card played inside it not; Vambrace's card kept the same way); crossed Art of War / Ripple Basin (attacks, until you've played one this turn); crossed Pocketwatch (the card that takes this turn past its limit of cards, 3, giving up next turn's 3 extra draws; each play of a replay and each auto-play counts, as the game counts them); crossed Pael's Tears (cards that would leave you with no energy once the play has resolved, since the relic only checks at the end of your turn: energy the play gets back first leaves you some, from the card itself (Production, Turbo and every card that gains energy when played, read from its code; Sunder on a kill, Bow Smack on an impaled target, Restlessness as your only card, Forgotten Ritual after an exhaust this turn, Double Energy, Mad Science's Energized rider, Epic Retrieval per arrow it knocks loose; Sown on its first play) or from what it sets off: Orbit, Automation, Subroutine, Yah, Ivory Tile, Nunchaku. Decision #117); crossed Pael's Eye (every card, while armed and nothing played this turn: playing one gives up the extra turn); one-shot Vambrace (block cards), Pael's Legion (block cards while it's off cooldown: double block; both only when the card's block is above 0 after the game's math: not under No Block (Panic Button), negative Dexterity or anything else that zeroes it, Entrench with no block, and only the first play of a replayed card; Adroit's block counts, so an Adroit attack gets them too), Burning Sticks (skills that exhaust when played; worked out from its code, decision #252), Unsettling Lamp (debuffing cards, temporary debuffs like Dark Shackles included, when some enemy you could debuff has fewer Artifact charges than the debuffs this play applies: the lamp ignores debuffs that Artifact blocks; the predictions double that play's Strength loss and poison), Music Box (attacks).

**Your attack against enemies** (from the card's damage to each enemy, through the game's damage math, times its hits, vs that enemy's block and HP). Hits match each card's own code: its hit count (HitCount from game v0.113.0; Repeat or a fixed count like Twin Strike's before), Whirlwind's X, a calculated count (Finisher, Flechettes...), or a condition (Dismantle on a Vulnerable enemy, Spite after you lost HP this turn, Fiend Fire per other card in hand), then the game's hit-count modifiers (Thumbscrew: one more on multi-hit attacks), as the card's own preview applies them. The Fool's cards: a Shoot card with no arrow to shoot does nothing (no damage counted); Nail hits only an Impaled enemy; Wah Blast hits twice once you've played a Cho or a Ki this turn. Damage goes through the game's math with the card's own damage properties, so arrow attacks get Aim (doubled by Heavy Shot), Dislike You and Quietus, and a shot made with Quietus loses its arrow once it impales (it never comes back to set off Yah or Twine: QuietusPower.AfterArrowShot, read from its code); on an enemy only your arrows Impale, hits after the one that knocks your last arrow out lose Serrated Arrows' and Wah Hammer's bonus. A replayed shot at an enemy that isn't Impaled impales it with its first play, so its later plays get Serrated Arrows' bonus (an arrow for each play, at most 3 hits a play, no Quietus). Rain Shot then deals its damage to every other enemy. A card that gains its block more than once (Cho Limbs, Cho Firm with an arrow, Second Wind per card) counts each gain in full:

## Outcome simulator

**While a play resolves (decision #28):** tags, Incoming Damage and the Death Skull show the board as it is, mid-play included; they don't run plays still resolving or queued (a teammate's can't always be seen). They settle once the play finishes. The play audit doesn't use them: it checks each play against a prediction made as that play begins.

One simulator behind Incoming Damage, every proc tag, the lethal tag, the Imbalanced and wake tags, and the audits (`mods/SpireQoL/Sim/`; design: docs/SIMULATOR.md, decisions #48, #49). The damage-formula audit compares each card's simulated first hit with the game's preview. It has no game types, so it's tested without the game (`tests/SpireQoL.Sim.Tests`, run on every push by the "Simulator tests" workflow).

The state after the play is still checked (the audit runs its own simulation).
**Searching every outcome (decision #107):** each simulation is one search on a worker thread. Every step (a hit, an orb, a block gain, a draw) advances every branch together, and branches that reach the same state merge, adding their shares of the rolls: the work grows with the distinct states, not with the orders of random targets, and nothing is sampled or dropped. The frame waits a few milliseconds for it at most (above); a search that takes longer goes on in the background (after its first 20,000 state copies it waits for a turn, half the CPU cores at most) and its result shows once it's over; until then the last result stays on screen. A new board cancels it; the forecast audit keeps its frozen forecast's search going and compares with all of it. Two caps stop a search: **memory**, 150,000 states held by every search together (about 2 KB each), past which a search holding at least an eighth of that stops; and **work**, 3 million state copies for one search (a chain inside one step that branches on every branch, like Beacon of Hope sharing block with Juggernaut on three or four players, holds little but runs on). A stopped search keeps the branches where it stopped, every share of the rolls with them: what's settled there still counts (an enemy already dead: its death chance shows as a range from that floor, a lethal tag as "75%?"), the play's own results are exact when the play was over before the cap, and everything else is unknown (Incoming Damage shows a lone ?). Every cap hit is logged (`[sim] cap:` which cap, steps, copies, states held, time), counted in the combat summary (`[perf] combat summary: searches stopped by`), and sent as an error report (`sim-cap`, decision #105: one per cap and kind, the turn forecast or a card's play, with the card as a tag and the start state to replay). Searches that went to the background are logged (`[sim] searched`: steps, copies, states held, outcomes, time). The combat summary also counts the frames shown with held tags or a held forecast. Branches share their orbs and teammates until one changes them (decision #23).
- Approximations: an orb's damage goes through the cap and the HP-loss pipeline but its unpowered amount isn't put through the damage math's modifiers (Hook.ModifyDamage), as before; a card's procs all land after its hits; a poison tick goes through the damage math the simulator models (a modifier it doesn't model isn't captured for it); Skittish reacts once to all of a replayed card's hits; a card's block split across several gains drops the remainder; auto-played cards get no procs from the proc rules (their hits, block, orbs and powers count). ## Shuffle Tag

**What you see:** a **discard pile** tag (the game's own discard pile icon) on cards in your hand whose play reshuffles your discard pile mid-turn: its draws run past your draw pile in every outcome of its simulation, at every target it can be aimed at (decision #193: the play's own log, the draws it sets off and a replay's later plays included). ## Intent Forecast

**What you see** (decisions #72, #73), during your turn, while you hover an enemy's intent (the intent icons, not the enemy): a backdrop-free stack right above the intent (a certain turn's intents centred over the intent on screen with its power icons to the right, kept level with the intent icon in their row as it bobs; the widget is frameless while locked) (beside it, to the right, when there's no room above; a movable widget) with its next moves after the intent on screen, a row per move stacked upward (`+1` nearest the intent, later turns higher; a random pick's moves at the top), each drawn with the game's own intent node (`NIntent`: the icon, its animation, bobbing in step with the intent on screen, and its damage number: what that attack will hit you for then, projected from the board with no plays of yours, below; as things stand now where that isn't known):
- **What a move applies:** small in the bottom-right corner of the buff or debuff intent it belongs to (as on the intent on screen: `Features/IntentCorner`, decision #99), each power the move applies, with its icon and amount (Frail 2), read from the move's own code (`Sim/Adapter/MovePowers`: its `PowerCmd.Apply` calls, and the amount passed in when it's a constant or a number the enemy keeps, read now, ascension included; the icon alone when the amount is worked out some other way). `IntentRulesTests` checks every buff and debuff move in the game names its powers.
- One row per turn, upward: the row just above the intent on screen is the turn after it, the next row up the one after (no turn numbers: the order says it). Every turn its move rules make certain is shown, up to three turns ahead.
- The first random pick ends the forecast: its moves side by side on one row, each with its chance above it (`45%`), so it stands apart from the certain turns below it.
- Nothing while its intent on screen is hidden (`HiddenIntent`, `UnknownIntent`): its rules would give the hidden move away. A future move whose intent is hidden shows hidden, as the game would.

**How it's worked out** (`Sim/IntentForecast`, pure and tested; `Sim/Adapter/IntentReader` reads the game): from the enemy's move rules (`MonsterMoveStateMachine`), the way the game picks its next move when the current one ends (`FindNextMoveState`): a move goes to its follow-up (the initial state when it has none); a random branch (`RandomBranchState`) picks by weight, a branch weighted 0 by its repeat rule never picked (`GetStateWeight`: `UseOnlyOnce` after its first use, `CannotRepeat` and `CanRepeatXTimes` after that many in a row, a cooldown over the last moves); a conditional branch (`ConditionalBranchState`) takes the first branch whose condition holds now. Weights and conditions are the game's own lambdas, read as things stand (an HP threshold, an ally's death, a counter): the forecast is "if nothing changes before the roll". A stunned enemy makes the move it lost next (`Creature.StunInternal`). It reads the moves the enemy has made this fight (`StateLog`), never the RNG: the turn after the intent on screen hasn't been rolled. A weight or condition that can't be read only stops the forecast where it's reached. Four enemies set moves outside their rules (Queen, Test Subject, Tough Egg, Waterfall Giant: `SetMoveImmediate`), which the forecast can't see.

**Its damage** (decision #304: `SimEngine.Project`, from Incoming Damage's own state of the board; `Sim/Adapter/SimAdapter.Projection`): each later attack shows what it will hit you for when it lands, with no plays of yours in between: the simulator plays out this turn's end and the enemy turn, the enemies' turn end (their Ritual, High Voltage and Territorial Strength, Weak and Vulnerable wearing off, each power's own code), then for each forecast turn your next turn (its start as the game runs it, every power's and relic's own turn-start code in its place: your poison ticking, Noxious Fumes poisoning the enemies, Brimstone's Strength on every living enemy, a power that goes as your turn starts, your Plasma orbs, decision #306; your block cleared; your hand left out, as you can't know what you'll draw, and so is what a card drawn then would set off; its end with no plays: your powers, relics and orbs), the enemies' turn start, every enemy's forecast move (a move that buffs itself before its attack counts its buff; an enemy that buffs another before it does too) and their turn's end. It follows only what the forecast shows (decision #308): every creature's powers (Strength, Weak, Vulnerable, Frail, Ritual and the like), relics and what they keep, and the enemies' moves and stuns; never anyone's HP or whether an enemy lives or dies (an enemy your poison would kill still shows its next attack), nor your hand, draws, energy or orbs, so a random hit on an enemy (an orb's Lightning, Juggernaut) is one outcome. Where a roll changes what it follows (another enemy's random pick, followed both ways with its chance), the number counts only what's certain: the attack as its intent reads when your turn starts, with what every outcome shares. An enemy past its own first random pick makes no move the projection counts. Where it isn't known (the simulator can't follow what comes first, a move whose code isn't read), the intent shows its damage as things stand now, as before. Drawn by a copy of the game's intent with that number (`Features/ProjectedAttackIntent`: the label, the sword's size and the hover tip all read it), only in the forecast; the intents the game shows are untouched. A power or relic whose turn-start code the simulator doesn't follow (read from its hooks: Mayhem's and History Course's plays, Countdown's Doom...) leaves that turn and the ones after it unknown; one whose code there touches only what a projection doesn't follow (Horn Cleat's and Captain's Wheel's block, Bread's and Amnesia's energy, Tools of the Trade's pick, Blessed Antler's Dazed) doesn't. **Its moves** (decision #309): once the projection is over, the later turns' moves are the ones it rolled from each enemy's move rules on the projected state, as the game rolls them as your turn starts: a condition on a power the projection follows (a sleeper's Asleep or Slumber, its last stack gone at the enemies' turn end) reads as it will stand then, so Lagavulin Matriarch and the Slumbering Beetle show their first attack the turn after their last stack, not another sleep; a condition on HP reads as it stands now, and one that isn't read as the game answers it now. A stun the projection sees coming ends the forecast there. Until then, and for an enemy whose rules can't be read, the moves are the game's rules as they answer now. The projection searches on a worker (decision #305: the frame waits 8 ms at most, as for every search): until it's over, the later attacks show their damage as things stand now, then take their projected numbers.

**Checked** (`IntentForecastAudit`): each time the game rolls an enemy's next move, the forecast for that roll is worked out from the state at that moment and compared with the move it picked: a certain forecast must match, a random one must have given it a chance above 0; every roll is logged with its odds (`[audit] [intent]`). The catalog tests read every enemy's move rules in the installed game (`IntentRulesTests`). For an enemy with conditional branches, the same moment also checks each branch's condition as the simulator reads it from the lambda's code (`MoveConditions`, decision #195: its HP against a breakpoint, a power it has, its side's living creatures, a flag of its own as it stands) against the game's own lambda on the same board; a difference is reported as a mismatch. The later turns' moves read them on the projected state (decision #309, below); `ConditionalBranchTests` holds every branch of every enemy in the game to the same. The projection (decision #304) is frozen as your turn ends (the forecast audit, from the same board as its own forecast) and, as your next turn starts, each enemy's rolled move, when the forecast gave it, must read what the projection said its intent would read then (each hit's `GetSingleDamage`); a mismatch is reported (named as such where a roll had left the number counting only what's certain), and a turn it can't hold is counted by reason (what the simulator can't follow, a card played after your turn ended, an enemy's death since, which a projection doesn't work out, a move the forecast didn't give); where the projection rolled an enemy's next move from its rules and the game rolled another, that's reported too.

**Settings:** the `intent-forecast` switch (In fights).

### Event Reminders

Setting: **Event Reminders** (`event-reminders`, on by default), with **Inspect event cards** (`EventInspect`) under it and **Chance under event icons** (`EventOdds`) under Show chances. **Patches:** `EventOption.Chosen` (observe-only prefix and postfix: the check).

**Events:** beside each event option (to its left), the icons of your relics that change what it does; crossed (red slash) when the relic works against you. What an option does is read from the option's own code, the game commands it runs (`EventOption`'s OnChosen, following the event's own methods and the delegates the event holds when the option calls one (the Endless Conveyor's current dish), the event's own parts it creates (`MegaCrit.Sts2.Core.Events.Custom`: the Crystal Sphere's minigame and the items it hides, so its card rewards, curse, gold and potions count) and a game mode's reward code (Blitz's Neow pick, `BlitzRunModel.GiveNeowRewards`) but not the options it opens next; a card it makes that is a curse (any call given a curse card's class, `ModelDb.Card` or `RunState.CreateCard` alike, a curse's constructor, the curse pool: Wuppy's Injury, Hefty Tablet's Injury, the Museum of Torture's pick) counts as adding a curse, whatever command adds it; for an ancient's relic option, also that relic's `AfterObtained`). **Which cards an option can give** (docs/CARD_ODDS.md, decision #58): read from the same code, through the game calls that make cards: a reward's `CardCreationOptions` (its pools: a character's, yours or the one the code names, such as Sea Glass's, or `ModelDb.CardPool<T>`, or the pool the option passes in as Colorful Philosophers does; and its filter, the lambda run on each card of the pool, as `GetPossibleCards` and `FilterForRun` do, or every card when the lambda holds a value set while the option runs, such as Glass Eye's rarity), fixed cards (`ModelDb.Card<T>`, `CreateCard<T>`, `CardCmd.TransformTo<T>`), a random transform (`CardCmd.TransformToRandom`, `CardFactory.CreateRandomCardForTransform` as Pandora's Box does: `CardFactory.GetDefaultTransformationOptions` of each card in your deck) and pools used directly (the Museum's curses). The eggs and Fresnel Lens show only when one of those cards is one they change, by their own test (`Data/CardAffinity.cs`: the egg's card type, upgradable and not upgraded; Fresnel Lens `Nimble.CanEnchant`, a card that gains block). An option whose cards can't be read keeps the icon. A curse, a Power-only reward with Molten Egg and the like show nothing.

The same goes for the relics that make certain cards stronger in fights in a way the card doesn't show (decision #59): Strike Dummy and Fake Strike Dummy (Strikes), Vitruvian Minion (Minion cards), Miniature Cannon (upgraded Attacks), Mystic Lighter (enchanted Attacks). Each counts the cards a card makes when played, read from its code (Begone! makes a Minion Strike, a Strike and a Minion), and the change your other relics make to the card you get (an egg's upgraded Attack for Miniature Cannon, Fresnel Lens' Nimble on an Attack for Mystic Lighter). Miniature Cannon also shows on options that upgrade a card of yours when an Attack of yours can be upgraded, Mystic Lighter on options that enchant one when an Attack of yours can take one of the enchantments the option names (`EnchantmentModel.CanEnchant`; Tezcatara's Nutritious Soup enchants your Strikes with Tezcatara's Ember), without a chance: you choose or it's sure. An option that upgrades the cards it gives (Astrolabe) counts them as upgraded: the eggs don't show, Miniature Cannon does. Cannon and Lighter add to an Attack's damage only (`IsPoweredAttack`), read as the card being an Attack.

**The chance** (docs/CARD_ODDS.md, `Sim/CardOdds`, tested), as a small number along the bottom of the icon: that at least one card you're offered is one the relic applies to. Read from the option's code and built by the game's: each reward's options are made by the same factory or constructor with its flags and passed through `Hook.ModifyCardRewardCreationOptions` (Dingy Rug's colorless cards, Prismatic Gem's other characters' cards), and a filter set per pass of a loop (Glass Eye's 2 commons, 2 uncommons and a rare) is read once per value; its rarity odds (`ForNonCombatWithDefaultOdds`: the regular encounter base odds from `CardRarityOdds.GetBaseOdds`, no rarity offset since events roll with base odds; `ForNonCombatWithUniformOdds`: every card equally likely) and how many cards it offers (a constant, or the event's or relic's own `DynamicVars`, as Colorful Philosophers' `Cards` and Sea Glass's `Cards / 3`). Each slot rolls a rarity (a rarity with no card left goes to the next one up), the card is uniform within it, and no card is offered twice; several rewards on one option combine. A random transform shows the chance the new card is one: one value, the same for every ordinary card (a card can't become itself, so it's taken from the card with the most results), and a range only when your deck has cards that transform from another pool (colorless for event, ancient and token cards; every rarity for a curse). None at 100% (a fixed card it applies to), and none when it can't be told: a count or odds the code doesn't show, a pool used directly, rewards mixed with transforms. Not counted: the upgrade roll of Colorful Philosophers' rewards (the other events turn it off). It's the rule's chance, never the roll. The number can be turned off: **Chance under event icons** (Between fights page, under Event Reminders; Show chances off hides it too; on by default). What the icons are for (decision #60): a reminder that a relic makes this choice unusually good or bad; the planned Inspect dialog is for the odds of an outcome you'd like.

**Check:** when you choose an option, the state before and after it (your deck's cards, gold, HP and max HP, potions) and the reminder relics that flashed while it ran are compared with what its code was read as doing and the icons shown. Reported (`reminders`): a relic that reacted with no icon; an effect that happened that the code wasn't read as having (a card or curse joining the deck, transforms included, gold not paid by Lucky Fysh, HP lost without max HP lost, a potion); an icon whose effect happened while its relic, which always reacts to it, didn't (Bing Bong, Lucky Fysh and Darkstone Periapt on cards, Tungsten Rod on HP loss, Bowler Hat and Dragon Fruit on gold). Only logged: an icon whose relic didn't react, and an effect read from the code that didn't happen (an empty card choice, a reward you leave, full potion slots). The window ends just after the option's task does, or when a fight starts. When the run ends with the option (a win's last Proceed: the game sets your HP to 0 as it closes the run), it's logged, not checked. Each choice writes an `[audit] [reminders]` line to the log.

**Inspect** (decisions #60, #64): right of an event option that gives cards at random from a known pool (a reward, a transform of a card you pick, a pool the code picks from; not a transform you don't choose, such as Pandora's Box's Strikes and Defends, which draws from your whole pool), a magnifier (the game's inspect cursor, `packed/common_ui/cursor_inspect.png`). It opens a screen (our own CanvasLayer `SpireQoL_Inspect`, game hotkeys blocked while open, Esc closes) listing every card the option can give, as the game's own cards, grouped as the option draws them: a group per reward (identical rewards merged, "2 rewards like it"), the pool a transform draws from, the cards it always gives. The same reading as the chance under the icons (the reward's options built by the game, through `Hook.ModifyCardRewardCreationOptions`). Click cards to mark the ones you'd be happy with: a marked card gets a ring around it (and its tags), the others are darkened (never made see-through); each group shows the chance it offers at least one (`Sim/CardOdds`), and the header the chance across the rewards. A reward that rolls its rarity first (`CardFactory.CreateForReward` with rarity odds: most events' rewards, Infested Automaton's Study among them) says so, with each rarity's chance ("rarity first: rare 1.5%, uncommon 98.5%": the base odds, a rarity with no card moving on to the next), and lists only the Common, Uncommon and Rare cards the roll can land on; uniform odds and transforms are an even chance per card. Your relics that apply to a card (`Data/CardAffinity.cs`) show their tag on it, with a button per relic that marks all its cards. For a transform, **Card you transform** picks a card from your deck and lists exactly what it can become (`CardFactory.GetDefaultTransformationOptions`). Marks are kept for the run while the game runs (a player's own notes; not saved). Every card the rules allow, never the roll. Setting `EventInspect`.

## Rest Preview

**What you see:** at a rest site, a sum beside your character (a movable widget, attached on your character's outer side at the fire: left of it when it sits left of the screen's middle, right of it when it sits right (in multiplayer the players sit on both sides; decision #100), the other side when there's no room; a teammate's panel the same way; drag it when the layout is unlocked), drawn like [Incoming Damage](#incoming-damage)'s:
- the top bar's heart and your HP now;
- the Rest option's icon and what resting heals (30% of max HP, rounded down, capped at your max);
- a line per relic or modifier that changes it, with its icon: Regal Pillow (+15, its own line), Stone Humidifier (+5 max HP, which also heals 5), Night Terrors (heals to full, then −5 max HP: a red line);
- at the last rest site before the boss (the boss's map point is next), a line for Pantograph (heals 25) and an unused Bath Robes (heals to full): the result is then the HP the boss fight starts with;
- under the rule, `= HP/max` after all of it, and in orange how much of the rest heal is wasted (past your max HP, or healed anyway by Pantograph or Bath Robes).

Shown while Rest is on offer and not yet chosen (the game's own list of your remaining options), or before the boss with one of those relics (then without the rest lines). Once you click Rest the rest lines go away at once, even while the heal plays out.

**Mend (multiplayer):** while Mend is on offer, hovering a teammate's character shows the same sum for them beside their character (widget "Mend Preview"): Mend heals them exactly as their own Rest would, with their relics (Regal Pillow, Stone Humidifier, Pantograph, Bath Robes), the run's Night Terrors, and the option's own Mend icon. Their relics are on screen for everyone, so it uses nothing a player couldn't know.

**Rules** (decompile v0.113.1, `Sim/RestMath`, tested): the heal is the game's own (`HealRestSiteOption.GetHealAmount`, `MendRestSiteOption.GetHealAmount` for the target: 30% of max HP through `ModifyRestSiteHealAmount`: Regal Pillow +15, Night Terrors to full), and HP becomes the whole part of HP + heal, capped at max. After it (`AfterRestSiteHeal`, on the healed player), Stone Humidifier adds 5 max HP (and HP), Night Terrors takes 5 max HP. At the boss fight's start (`BeforeCombatStart`), Pantograph heals 25 and Bath Robes heals to full, once.

**Check:** after you rest, your HP and max HP against the preview (`[audit] [rest]`, reported as `rest-heal`); after your Mend, the teammate's (`rest-mend`); at the boss fight's start, your HP against the preview for how you left the last rest site (`rest-boss`).

**Settings:** the `rest-preview` switch (Between fights page).

**Game UI touched:** nothing of the game's: the panels are our own widgets (ids `rest-hp`, `rest-mend`); read: `NRestSiteRoom.Instance`, its characters (`characterAnims`, `GetCharacterForPlayer`, each `NRestSiteCharacter.Hitbox`'s place and whether the mouse is over it), `RunManager.Instance.RestSiteSynchronizer.GetLocalOptions()` (Rest and Mend on offer). **Patches:** `HealRestSiteOption.OnSelect` (observe-only prefix: the check records the preview you chose from, and Rest stops being offered), `MendRestSiteOption.OnSelect` (observe-only prefix and postfix: the Mend check, and Mend is offered again if you cancel the targeting).

## Update Notice

**What you see:** on the main menu, when newer Spire QoL versions are out, a small green note just above the game's "MODDED (n)" text in the bottom-right corner: "Spire QoL: 3 versions behind (new version on GitHub)". Clicking it opens the newest Spire QoL release on GitHub (its notes and download); when you're up to date, Spire QoL's releases, searched by its tag so the repo's other mods' releases are left out. When GitHub confirms you're on the newest version, a muted grey "Spire QoL up to date!" instead. Nothing when GitHub can't be reached, and nothing during a run.

**Checking:** while GitHub hasn't answered yet (the first visit to the menu), the note reads "Checking for Spire QoL updates…" in a faint grey, so it doesn't seem missing.

**Settings gear:** to the right of the note, the game's own top-bar settings gear (`images/packed/common_ui/top_bar/top_bar_settings.png`); clicking it opens the Spire QoL settings menu. It shows on the main menu even while GitHub hasn't answered or can't be reached (alone, where the note would be), and goes with the `update-notice` switch.

**Test builds:** a build whose version isn't one of the releases, or that was built with uncommitted changes, shows two orange lines there instead: its version, the commit it was built from (stamped by the SDK), whether it has uncommitted changes (`GitDirty`, stamped by `Directory.Build.targets` from `git status`) and when it was built; then whether its version number is already released, the newest release, and how many are newer. Release builds are made from a clean commit, so players never see this.

**How it checks:** each time the main menu appears, one request on a worker thread to GitHub's public releases list for this repo (every page, 100 releases each), counting `spireqol-v<version>` releases (not drafts or prereleases) newer than the running DLL's version. It sends nothing about you; the User-Agent is the mod's id. If GitHub can't be reached, the note keeps its last answer (or stays hidden: it never says you're up to date without checking). Turn it off with the `update-notice` switch (settings menu, General).

**Game UI touched:** adds a label and the gear as children of the main menu's `%ModdedWarning` label (`NDebugInfoLabelManager`); the game's own label isn't changed. No Harmony patches.

## Main Saves (separate mod)

**What it does:** while any mod is loaded, the game keeps its saves in a separate `modded` folder (`%APPDATA%\SlayTheSpire2\steam\<id>\modded\`: `profile.save` and every profile's progress, current run, prefs and run history), copied from the normal saves only the first time you play modded. Main Saves makes the game use the normal folder instead, so modded and unmodded play share one set of profiles. The game still knows it's running modded (run history and its own crash reporting behave as with any mod). No settings. Remove the mod to go back to the modded profiles, which are left as they were.

**Harmony patch:** `UserDataPathProvider.GetAccountDir` (prefix): returns the normal folder (`""`) when the game asks for the current mode; calls that name a mode (`forceModState`, the game's first-time copy into `modded`) get the game's own answer. Unlike Spire QoL's, this patch changes what the game does (decision #33).
